# /unit-plan $ARGUMENTS

단위 **U$ARGUMENTS**의 설계 메모를 쓴다. **이 명령으로는 코드를 쓰지 않는다.**

## 1. 읽기
- `docs/units/R0.md`(또는 현재 단계 계획)에서 U$ARGUMENTS 행과 "정해 둔 방향"
- `docs/design.md`에서 이 단위와 관련된 절. 특히 §2 원칙, §5 버전, §8 저장
- 앞 단위 메모(`docs/units/U*.md`)의 "결과"와 "남은 일"
- 이미 있는 코드: 다시 쓸 수 있는 함수와 타입을 찾는다

## 2. 메모 쓰기: `docs/units/U$ARGUMENTS.md`

아래 칸을 이 순서로 쓴다.

```markdown
# U<n> <제목>

상태: 설계 (검토 대기)
관련: docs/design.md §…, docs/units/R0.md

## 목표
## 만들 것
## 파일            (새로 만들 파일, 바꿀 파일)
## 완료 기준       (번호 목록. 모두 시험이나 명령으로 확인 가능해야 함)
## 시험 목록
## 설계와 다른 점  (없으면 "없음")
## 결정 필요       (사람이 정해야 할 것. 제안을 함께 적음)
```

- 완료 기준은 "동작한다"처럼 흐리게 쓰지 않는다. 확인 방법(시험 이름·명령)을 단다.
- R0.md의 "정해 둔 방향"을 확정한 내용은 메모에 적는다.

## 3. 검토
- `design-reviewer` 에이전트를 부른다. 메모 경로만 넘기고, 내 결론은 넘기지 않는다.
- 지적을 반영하거나, 반영하지 않는 이유를 메모 끝 "검토 반영" 절에 적는다.

## 4. 멈춤
- 메모 요약(만들 것, 완료 기준, 결정 필요)을 사람에게 보여 주고 **승인을 기다린다**.
- 승인 전에는 구현하지 않는다.
