# /unit-report $ARGUMENTS

`docs/units/U$ARGUMENTS.md` 끝에 "결과" 절을 덧붙이고, 머리의 `상태:`를 갱신한다.

## 쓰는 내용

```markdown
## 결과 (YYYY-MM-DD)

### 완료 기준
| # | 기준 | 결과 | 근거 |
| --- | --- | --- | --- |
| 1 | … | 통과 / 실패 / 확인 못 함 | 시험 이름, 명령 출력 요약 |

### 설계와 달라진 점
### 남은 일 (다음 단위나 나중으로)
### 고정한 버전 (도구·액션·의존성, 바뀐 것만)
```

## 규칙
- 근거는 이번 세션에서 **실제로 돌린** 명령과 시험만 적는다. 돌리지 않은 것은 "확인 못 함"으로 적고 이유를 단다.
- 설계와 달라진 점이 있으면 `docs/design.md`도 고쳤는지 확인한다.
- 커밋 메시지 초안(한국어, `종류: 요약` + 본문 목록)을 사람에게 보여 준다. push·PR은 따로 묻는다.
- CI 완료 기준은 결과를 적지 않고 `CI: PR #n`만 적는다. CI 결과(작업별 통과, run 번호)는 PR 본문에 `gh pr edit --body-file`로 적는다. 결과 기록용 커밋은 만들지 않는다.
