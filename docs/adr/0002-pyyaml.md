# ADR 0002: 구성 YAML은 PyYAML(SafeLoader)로 읽는다

- 상태: 채택 (2026-11-17, U2)
- 결정한 사람: 석한나

## 맥락

실험 조건은 YAML 하나에 적는다(설계 §5). 파이썬 표준 라이브러리에는 YAML 파서가 없다. 후보는 두 가지였다.

- **PyYAML 6.0.3**(MIT): 가장 널리 쓰이고 가볍다. `SafeLoader`가 있다.
- **ruamel.yaml 0.19**(MIT): YAML 1.2, 주석 보존. 더 무겁다.

U2에서 YAML은 읽기만 한다. 주석 보존이 필요 없고, 원문은 텍스트로 따로 보존한다(`LoadedConfig.raw_text`).

## 결정

런타임 의존성 **PyYAML**을 추가하고(`pyyaml>=6.0.3`), 타입 정보 `types-PyYAML`을 개발 의존성으로 둔다.

- **안전한 읽기만 한다**: `yaml.SafeLoader`를 상속한 로더만 쓴다. 임의 객체 생성(`yaml.Loader`, `!!python/…`)은 쓰지 않는다.
- PyYAML 기본 동작 중 위험한 것은 로더를 작게 고쳐 막는다.
  - 중복 키는 조용히 덮어쓰는 대신 오류로 한다.
  - 날짜처럼 생긴 값(`2026-11-17`)을 날짜 객체로 바꾸지 않고 문자열로 둔다.
  - JSON 값이 아닌 것(`!!binary`, `!!set`, 사용자 태그)은 오류로 한다.
  - 파싱 오류 메시지에는 줄·칸 번호만 넣고 원문 조각은 넣지 않는다(비밀값이 섞일 수 있음).
- YAML 1.1의 `yes`/`no` → bool 변환은 그대로 둔다. bool이 들어오면 안 되는 칸은 pydantic 스키마가 거부한다.
- YAML 1.1은 소수점 없는 지수 표기(`1e-3`)를 문자열로 읽는다. YAML 1.2처럼 float로 읽도록 해석 규칙을 하나 더한다(`temperature: 1e-3`과 `0.001`이 같은 해시).
- 원문 검사(주소·비밀값)는 파서가 아니라 원문 텍스트를 줄 단위로 한다. 파서는 주석을 버리기 때문이다.

## 결과

- 좋은 점: 가볍고 널리 쓰인다. 안전 로더와 오류 처리만 고치면 충분하다.
- 나쁜 점: YAML 1.1 규칙(`on`/`off` 등)이 남는다. 주석을 보존해 다시 쓰는 기능(R1 화면에서 YAML 저장)이 필요해지면 그때 ruamel.yaml을 다시 검토한다.
- 버전: PyYAML 6.0.3, types-PyYAML 6.0.12.20261113(`uv.lock`)
