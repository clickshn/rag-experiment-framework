# ADR 0003: 모델 호출은 httpx를 직접 써서 한다

- 상태: 채택 (2026-11-17, U3)
- 결정한 사람: 석한나

## 맥락

모든 모델 호출은 한 클라이언트 층을 지난다(설계 §4 "모델 호출 통로"). 이 층은 시간 제한·재시도·지연 기록·응답 모델 이름 확인·잘림 구분을 하고, 주소·키·응답 본문이 오류 문구로 새지 않게 해야 한다. 표준 라이브러리에는 쓸 만한 HTTP 클라이언트가 없다(`urllib`은 시간 제한을 연결·응답으로 나누기 어렵고, 가짜 전송 계층을 끼울 길이 없다). 후보는 세 가지였다.

- **OpenAI 공식 SDK**(`openai`): 자체 재시도·시간 제한이 있다. 하지만 재시도 규칙(분류 셋, 시간 초과 2번 상한, `Retry-After` 상한)을 우리 규칙으로 바꾸기 어렵다. 예외 문자열에 요청 주소가 들어가고, 의존성이 크다. 응답 객체가 서버마다 다른 칸(vLLM 확장 등)을 엄격하게 다루는 경우가 있다.
- **httpx 0.28**(BSD-3-Clause): 연결·응답 시간 제한을 따로 정할 수 있다. `MockTransport`로 소켓 없이 시험할 수 있다. 동기·비동기를 같은 API로 쓴다. OpenAI SDK도 안에서 httpx를 쓴다.
- **requests**: 널리 쓰이지만 가짜 전송 계층을 끼우기가 httpx보다 번거롭고, 비동기가 없다(U6 동시 처리에서 필요해질 수 있음).

설계 §9.1은 모델 호출을 "OpenAI 호환 SDK(httpx)"로 정해 두었고, R0 계획(`docs/units/R0.md`)은 "httpx를 직접 쓴다"로 정했다.

## 결정

런타임 의존성 **httpx**를 직접 명시한다(`httpx>=0.28.1`). OpenAI SDK는 쓰지 않는다.

- `src/ragexp/client.py`의 `ChatClient`만 httpx를 부른다. 부품은 이 클라이언트를 쓴다.
- httpx 예외는 종류(클래스)만 보고 `error_kind`로 바꾼다. 예외 문자열(주소가 들어 있음)은 쓰지 않는다.
- 리다이렉트는 따라가지 않는다(`follow_redirects=False`). 3xx는 모르는 상태 코드로 다룬다.
- 시험은 `httpx.MockTransport`와 표준 라이브러리 `http.server` 가짜 서버로 한다(네트워크 없음).
- httpx·httpcore 로거는 INFO 수준에서 요청 주소를 찍는다. 로깅을 설정하는 U6에서 WARNING으로 묶는다(설계 §5 "알려진 남는 위험").

## 결과

- 좋은 점: 재시도·분류·문구를 우리 규칙대로 한 곳에서 정한다. 가짜 전송 계층으로 대응표의 모든 행을 소켓 없이 시험한다. 같은 클라이언트를 임베딩·리랭크(R2)로 넓히기 쉽다.
- 나쁜 점: OpenAI 응답 형식의 변화(새 칸, 스트리밍 등)를 직접 따라가야 한다. R0는 `choices[0].message.content`·`finish_reason`·`usage`·`model`만 읽으므로 범위가 작다.
- 버전: httpx 0.28.1, httpcore 1.0.9, h11 0.16.0, anyio 4.16.0, certifi 2026.10.23, idna 3.20(`uv.lock`)
