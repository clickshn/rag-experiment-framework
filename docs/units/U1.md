# U1 도메인 타입·부품 인터페이스·등록

상태: 구현 완료, PR 대기 (메모 승인 2026-11-17)
관련: docs/design.md §4, §5, §6.3, §7.2, §8.1 · docs/units/R0.md · docs/adr/0001-pydantic-domain-types.md · 브랜치 `u1-types-registry`

> **승인 때 바뀐 결정 (본문보다 우선)**
> 1. 도메인 타입은 dataclass가 아니라 **pydantic `BaseModel(frozen=True)`**이다(ADR 0001). U5 문항 검증과 같은 정의를 쓰기 위해서다. pydantic 의존성은 U1에서 추가했다.
> 2. `Item` → `Question`, design.md도 함께 고친다.
> 3. entry point 이름은 **`<kind>.<name>`**이고, 값은 클래스(`모듈:클래스`)를 가리킨다.
>    - 불러오지 않고도 어떤 부품이 있는지 안다.
>    - 실제로 쓰는 부품만 그때 불러오고, 실패하면 플러그인 이름을 담아 멈춘다.
>    - 쓰지 않는 플러그인의 문제는 경고만 낸다.
> 4. fingerprint 금지 규칙은 3절 표에 더해 **절대 로컬 경로 값**(드라이브 문자, UNC, `/home/`·`/Users/` 등)도 금지한다. 스냅샷은 경로가 아니라 내용 해시로 넣는다.
> 5. 크기 M.

## 목표

R0의 모든 부품이 같은 말로 주고받게 하고, 설계 원칙 몇 가지를 **타입으로** 강제한다.

1. **도메인 타입 7개**가 깊은 불변 값이고, JSON으로 왕복된다.
2. **부품 Protocol 9개**가 정의된다. 모두 `fingerprint()`를 갖는다.
3. 구현을 **이름으로 등록·생성**한다. 외부 부품도 프레임워크를 고치지 않고 **entry point**로 붙는다.
4. 다음 원칙을 타입과 검사로 막는다.

| 원칙 | 막는 방법 |
| --- | --- |
| 정답 정보는 oracle 검색만 본다(공정 비교) | 검색 입력 `RetrievalQuery`, 생성 입력 `GenerationInput`에 gold·must·fail 칸이 없거나 비어 있음 |
| 판정은 블라인드다(§7.2) | 판정 입력 `JudgeInput`·`JudgeQuestion`에 모델·arm·provenance 칸이 없음 |
| 정오는 코드가 계산한다(§7.2) | Judge가 돌려주는 `Verdict`에 `correct` 칸이 없음. 정오는 U7의 순수 함수가 계산 |
| 주소·비밀값·meta는 해시에 넣지 않는다(§5) | `check_fingerprint`가 이름·값을 검사. `create`는 `meta` 키를 거부 |
| 주소는 실행 기록에 남기지 않는다(§8.1) | `Answer.error`·`Verdict.note`에 `://`가 있으면 생성 시 오류 |

실제 부품 구현은 이 단위에서 만들지 않는다(U4 이후).

## 만들 것

### 1) 도메인 타입 (`src/ragexp/types.py`)

공통 규칙:
- ~~`@dataclass(frozen=True, slots=True, kw_only=True)`~~ → **pydantic `BaseModel(frozen=True)`**(공통 바탕 `Frozen`)으로 만든다(승인 결정 1).
- **깊은 불변**: 생성 시 `Mapping` 칸은 재귀적으로 `MappingProxyType`, `list`는 `tuple`로 바꿔 저장한다. 넘긴 dict를 나중에 고쳐도 객체 값은 그대로다.
- **해시 가능**: 정규화한 표현(키 정렬, 숫자는 float)으로 해시한다. 같다고 비교되는 객체는 해시도 같다. 그래서 `Chunk` 등을 set에 넣을 수 있다.
- **JSON 왕복**: `to_dict()`·`from_dict()`를 둔다. U6 실행 기록이 이 형식을 그대로 쓴다.
- **생성 시 검증**: 빈 ID, 음수 토큰, rank < 1, NaN·inf 숫자, `0 ≤ must_min ≤ len(must)` 위반, `error`·`note` 안의 `://`는 오류다.
- `JSON` = `str | int | float | bool | None | tuple[JSON, ...] | Mapping[str, JSON]`

**핵심 7개**

| 타입 | 칸 | 뜻·규칙 |
| --- | --- | --- |
| `Document` | `doc_id`, `title`, `text`, `sections: tuple[Section, ...] = ()`, `meta: Mapping[str, JSON]` | 말뭉치 원문 한 건(법령이면 법령 하나). 조 단위 청킹은 `sections`를 쓴다. `meta`에는 출처 정보(법령 ID·시행일)만 둔다. |
| `Chunk` | `chunk_id`, `doc_id`, `text`, `heading = ""`, `meta` | 검색·근거의 단위. `chunk_id`는 문항 `gold`와 같은 체계다(형식은 U4에서 확정). |
| `Hit` | `chunk: Chunk`, `score: float`, `rank: int`, `source: str` | 검색·리랭크 결과 한 줄. rank는 1부터. **정답 여부 칸은 없다.** |
| `Question` | `qid`, `qtype`, `split: Literal["dev","val","test"] \| None`, `question`, `gold: tuple[str, ...]`, `must`, `must_min`, `fail`, `optional = ()`, `scoring_note = ""`, `answer_schema: Mapping \| None = None`, `expected_tool_calls = ()`, `provenance: Mapping` | 설계 §6.3 형식이다. JSON 키 `type`은 `qtype`으로 읽고 다시 `type`으로 쓴다. `split=None`은 아직 나누지 않은 초안이다. 답 없는 문항은 `gold=()`이다. |
| `Usage` | `input_tokens: int \| None`, `output_tokens: int \| None`, `latency_ms: float` | 모델 호출 한 번의 비용 재료. 서버가 토큰을 안 주면 `None`(0과 구분). |
| `Answer` | `text`, `finish_reason: FinishReason`, `usage: Usage`, `served_model: str \| None`, `error_kind: ErrorKind \| None = None`, `error: str = ""` | 생성기 출력. `FinishReason = Literal["stop","length","error","other"]`, `ErrorKind = Literal["connect","timeout","http_status","parse","other"]`. U6은 `connect`·`timeout`만 다시 돌린다. `error`는 주소를 지운 짧은 문장이다(U3이 만듦). |
| `Verdict` | `judge_id: str`, `judge_type: str`, `status: VerdictStatus`, `must: tuple[bool \| None, ...] = ()`, `fail: tuple[bool \| None, ...] = ()`, `metrics: Mapping[str, float \| None]`, `usage: Usage \| None = None`, `note = ""` | 판정 부품 하나의 출력. 칸 설명은 아래에 있다. |

`Verdict` 칸 설명:
- `judge_id`는 판정 인스턴스 ID다. 구성의 judges 목록에서 U2가 정해 주며, 같은 `llm` 판정 둘을 구분한다. `judge_type`은 등록 이름이다.
- `VerdictStatus = Literal["ok","truncated","error","not_applicable"]`
- **`correct` 칸은 없다.** 정오는 U7의 `decide(question, verdict)`가 계산해 따로 기록한다.
- `metrics`의 `None`은 "정의되지 않음"이다(예: gold가 빈 문항의 인용 재현율). 집계에서 빠진다(U7·U8).

**보조 타입**(원칙을 타입으로 막기 위한 것)

| 타입 | 칸 | 쓰는 곳 |
| --- | --- | --- |
| `Section` | `section_id`, `heading`, `text`, `meta` | `Document.sections`(법령이면 조문, `section_id="제27조의2"`) |
| `RetrievalQuery` | `text: str`, `gold: tuple[str, ...] \| None = None` | `Retriever.retrieve` 입력. 정답 근거가 필요한 검색기(`needs_gold = True`)에만, 그리고 `level=generation_only`에서만 runner가 `gold`를 채운다. 실제 강제와 그 시험은 U6이 맡는다. |
| `GenerationInput` | `question: str`, `qtype: str`, `answer_schema: Mapping \| None` | `Generator.generate` 입력. **gold·must·fail 칸이 없다.** JSON 문항의 스키마를 프롬프트에 넣거나 JSON을 강제하는 데 쓴다. |
| `JudgeQuestion` | `qtype`, `question`, `gold`, `must`, `must_min`, `fail`, `optional`, `scoring_note`, `answer_schema` | `Judge.judge` 입력. `Question.for_judge()`로만 만든다. **qid·split·provenance 칸이 없다**(provenance에는 초안 모델 이름이 들어 있음). |
| `JudgeInput` | `answer_text: str`, `finish_reason`, `context: tuple[Chunk, ...]` | `Judge.judge` 입력. `JudgeInput.from_answer(answer, context)`로만 만든다. **served_model·usage·arm 칸이 없다.** |

### 2) 부품 Protocol 9개 (`src/ragexp/components/protocols.py`)

모든 Protocol 공통:
- `@runtime_checkable`이다.
- 클래스 속성 `version: ClassVar[str]`이 **필수**다. 구현 동작이 바뀌면 올린다. 판정 규칙을 고쳤는데 채점 버전이 그대로인 일을 막기 위해서다.
- 메서드 `fingerprint() -> Fingerprint`를 갖는다.

| Protocol | 메서드 | 설계 §4 예시와 다른 점 |
| --- | --- | --- |
| `Corpus` | `documents() -> Iterator[Document]` | |
| `Chunker` | `chunk(doc: Document) -> list[Chunk]` | |
| `Embedder` | `embed(texts: Sequence[str], *, kind: Literal["query","document"]) -> list[list[float]]`, `dimension() -> int` | 질문과 문서를 구분한다(접두어가 다른 모델 대비). 차원은 메서드다. |
| `VectorStore` | `add(chunks, vectors) -> None`, `search(vector, k: int) -> list[Hit]` | |
| `Retriever` | `retrieve(query: RetrievalQuery) -> list[Hit]`. 클래스 속성 `needs_gold: ClassVar[bool] = False` | 입력이 `RetrievalQuery`다. k는 설정값이다. |
| `Reranker` | `rerank(query: str, hits: Sequence[Hit]) -> list[Hit]` | |
| `Generator` | `generate(inp: GenerationInput, context: Sequence[Chunk]) -> Answer` | 입력이 `str`이 아니라 `GenerationInput`이다(JSON 문항). |
| `Judge` | `judge(question: JudgeQuestion, response: JudgeInput) -> Verdict` | 블라인드 보기만 받는다. |
| `QuestionGenerator` | `draft(chunks: Sequence[Chunk], qtype: str, n: int) -> list[Question]` | R0는 Protocol만 둔다. 반환 초안은 `split=None`이다. R3에서 다시 정한다. |

레지스트리는 Protocol마다 **직접 적은 메서드 목록 표**로 등록 시 검사한다(3.12에는 `get_protocol_members`가 없음). 속성(`version`, `needs_gold`)은 클래스에서 확인한다.

### 3) fingerprint 규칙 (`src/ragexp/fingerprint.py`)

`Fingerprint = Mapping[str, JSON]`이다. 부품은 출력을 바꾸는 것만 내놓는다. 레지스트리가 여기에 `type`·`version`을 붙인다. 그 결과가 들어가는 곳은 U2에서 이렇게 갈린다.
- `kind=judge`의 fingerprint → **채점 버전**
- 나머지 부품의 fingerprint → **구성 버전**

| 넣는다 (바뀌면 다른 실험) | 빼는 것 (바뀌어도 같은 실험) |
| --- | --- |
| 등록 이름·구현 `version`(레지스트리가 붙임) | 서버 주소, API 키·토큰, `${VAR}` 이름 |
| 모델 이름·revision·임베딩 차원·정규화 여부 | 시간 제한, 재시도, 동시 처리 수 |
| 출력에 영향 주는 파라미터(temperature, max_tokens, top_p, seed, k, top_n, 청크 길이·겹침, 근거 글자 상한, 방해 덩어리 수·seed) | 모델 meta: 가격, GPU 메모리, 라이선스, 폐쇄망 반입 여부, 종료 예정일, deploy |
| 프롬프트·판정 템플릿 **내용**의 sha256 | 실행 환경 값(경로, 로그 위치) |
| 말뭉치 스냅샷 manifest 해시 | |

**`check_fingerprint(fp, allow=frozenset()) -> dict`** — 이름 검사는 어느 깊이에서든 하고 대소문자는 무시한다.

| 검사 | 규칙 |
| --- | --- |
| 값 종류 | JSON 값만 허용. NaN·inf·bytes·객체는 거부. 키는 str만 |
| 금지(정확한 이름) | `base_url`, `api_base`, `url`, `endpoint`, `host`, `api_key`, `access_token`, `auth_token`, `secret`, `password`, `meta` |
| 금지(meta 칸 이름, 설계 §4·§5) | `gpu_cost_per_hour`, `vram_gb`, `license`, `deploy`, `air_gapped`, `end_of_life` |
| 금지(끝말) | `_key`, `_secret`, `_password`, `_token`(단수. `max_tokens`·`chunk_tokens`는 해당 없음) |
| 금지(접두어) | `price`, `auth` |
| 값에 금지 | 문자열에 `://`가 있거나 `${`로 시작하면 거부(주소·치환 자리) |

- **허용 예외는 부품이 직접 선언한다.** 클래스 속성 `fingerprint_allow: ClassVar[frozenset[str]]`에 적으면, 프레임워크를 고치지 않고 예외를 둘 수 있다(예: `stop_token`).
- **정규화**는 `tuple→list`, `Mapping→dict`만 한다. 숫자는 바꾸지 않는다(`1`과 `1.0` 처리는 U2 해시 규칙에서 정함). 키 정렬도 U2에서 한다.

### 4) 등록 (`src/ragexp/registry.py`)

**import 부작용에 기대지 않는다.** 데코레이터는 표시만 하고, 등록은 각 `Registry`가 한다.

- `ComponentKind = Literal["corpus","chunker","embedder","vector_store","retriever","reranker","generator","judge","question_generator"]`

**`@register(kind, name)`**
- 클래스에 `__ragexp_component__ = (kind, name)` 표시만 붙인다. 전역 상태는 바꾸지 않는다.
- Protocol 충족 검사(메서드 표, `version` 필수)는 이 시점에 한다. 정의를 잘못하면 import할 때 바로 드러난다.

**`Registry` API**
- `add(cls)`: 표시된 클래스를 등록한다.
- `add_module(module)`: 모듈 안의 표시된 클래스를 모두 등록한다.
- entry point(승인 결정 3): 그룹 `ragexp.components`, 이름 `<kind>.<name>`, 값 `모듈:클래스`.
  - **레지스트리마다 따로** 이름만 한 번 찾는다(불러오지 않음).
  - 이름 형식이 틀린 entry point는 경고하고 건너뛴다.
- `available(kind)`: 등록된 이름과 entry point 이름을 합쳐 돌려준다. 플러그인을 불러오지 않는다.
- `get(kind, name)`: 쓰는 부품만 그때 불러온다(레지스트리마다 한 번).
  - 다음 경우는 플러그인 이름을 담은 `RegistryError`로 멈춘다: 불러오기 실패, 클래스가 아님, 표시가 이름과 다름, Protocol 미충족, 두 플러그인이 같은 이름.
- `load_all()`: 점검용으로 모든 플러그인을 불러와 본다. 실패는 경고만 하고, 실패한 이름 목록을 돌려준다.
- `create(kind, name, config)`
  - config에 `meta` 키가 있으면 거부한다(meta는 U2가 떼어 낸 뒤 넘긴다).
  - U1에서는 `cls(**config)`로 만든다.
  - 생성자 오류는 **키 이름만** 담은 `RegistryError`로 바꾼다. 값(주소·키)은 메시지에 넣지 않는다.
- `component_fingerprint(obj)`
  - obj 클래스의 표시에서 kind·name을 거꾸로 찾는다. 따로 넘긴 이름과 실제 클래스가 어긋날 여지를 없앤다.
  - 이 레지스트리에 등록된 클래스인지 확인한다.
  - 결과는 `{"type": name, "version": cls.version, **check_fingerprint(obj.fingerprint(), cls.fingerprint_allow)}`이다. 부품이 `type`·`version`을 직접 내면 오류다.
- `default_registry()`: 앱이 쓰는 전역 하나. 시험은 `Registry()`를 새로 만든다.

**설정 스키마 자리**: 클래스 속성 `config_model: ClassVar[type | None] = None`을 약속에만 미리 둔다. U2가 Pydantic 모델을 넣어 `create`의 검증과 §8.2 설정 폼에 쓴다. U4 부품이 U2와 나란히 만들어져도 약속이 바뀌지 않게 하려는 것이다.

**오류**(모두 `RegistryError`):
- 모르는 kind
- 모르는 name: 등록된 목록과 비슷한 이름 제안(difflib)을 함께 보여 준다.
- 중복: 같은 kind·name에 다른 클래스. 같은 클래스를 다시 등록하면 무시한다.
- Protocol 미충족
- `version` 없음
- 플러그인 불러오기 실패: entry point 이름과 원래 예외를 담는다. **멈춘다**.

내장 부품도 U4부터 같은 그룹으로 `pyproject.toml`에 선언한다.

## 설계와 다른 점

설계 §4 예시를 아래처럼 바꾸고 design.md도 함께 고친다.

| 바뀌는 것 | 이유 |
| --- | --- |
| `Item` → `Question` | U6의 실행 단위(문항 × arm × 반복)를 "RunItem"이라 부르므로 섞이지 않게 한다. |

## 결정 (승인 2026-11-17)

아래는 승인 전 제안이다. 결과는 머리의 "승인 때 바뀐 결정"을 따른다.

1. **타입 구현 방식.** 제안은 표준 라이브러리 frozen dataclass다. 바깥 입력(구성·문항 파일) 검증은 U2·U5에서 Pydantic으로 한다. 대안은 Pydantic frozen 모델인데, U1부터 의존성이 생기고 실행 기록 한 줄마다 검증 비용이 든다.
2. **`Item` → `Question` 이름 바꾸기.** 제안은 바꾸는 것이다.
3. **외부 부품 불러오기 실패.** 제안은 "멈춤"(재현성 우선)이다. 대안은 경고만 내고 건너뛰기다.
4. **fingerprint 금지 규칙.** 3절 표를 그대로 쓸지, 더할 이름이 있는지 정해 주세요.
5. **크기.** R0.md의 S를 **M(1일)**으로 다시 잡는다. 이유는 원칙 타입 4개와 entry point 시험이다.

### 설계와 달라진 점

- **승인 결정 1~5**: 머리의 "승인 때 바뀐 결정"에 적었다.
- **`Answer`의 오류 칸 짝 규칙**: `error_kind`는 `finish_reason == "error"`일 때만, 그리고 반드시 채운다(메모에 없던 규칙). U3·U6은 이 규칙에 맞춰 Answer를 만든다.
- **`needs_gold`는 Protocol 멤버가 아니다**: 선택 클래스 속성이라 docstring에만 적었다. 레지스트리는 값이 bool인지만 검사한다. U6이 `getattr(cls, "needs_gold", False)`로 읽는다. `fingerprint_allow`·`config_model`도 같은 방식이다.
- **mypy `exclude`를 쓰지 않았다**: 깨진 플러그인 fixture(`raise ImportError`만 있음)도 mypy를 통과한다. 대신 훅 시험을 위해 `mypy_path = [".claude/hooks"]`를 넣었다.

### 남은 일 (다음 단위)

- **vLLM 모델 경로**(결정 필요): vLLM은 `--served-model-name`을 주지 않으면 `/models/Qwen…`처럼 모델 경로를 모델 이름으로 쓴다. 이 값은 절대 경로 규칙에 걸려 fingerprint에서 거부된다(서버마다 해시가 달라지는 것을 막음). U2·U3 메모에서 정한다. 제안: `--served-model-name`을 쓰라고 안내한다.
- **U4 entry point 시험 격리**: U4에서 내장 부품을 이 프로젝트의 entry point로 선언하면, `Registry()`가 그것도 읽는다. 시험이 목록을 정확히 비교하지 않도록 이미 고쳤다. U4에서 다시 확인한다.
- **U6 로그 경로**: 플러그인 불러오기 실패 메시지에는 원래 예외 문자열이 들어간다(로컬 경로가 있을 수 있음). U6에서 실행 기록·로그에 이 메시지를 남기지 않는지 확인한다.
- **U6 gold 강제**: gold를 `needs_gold` 검색기에만, 생성만 수준에서만 넘기는 강제와 그 시험은 U6에서 한다.
- **`model_construct`**: 검증을 건너뛰므로 쓰지 않는다(docstring에 적음). 코드로 막지는 않았다.
