## 목표

실험 조건을 YAML 하나로 읽어 검증하고, **다시 돌려도 같은 버전**이 나오는 해시를 만든다. 해시에 들어간 원재료를 함께 남겨, 실행 기록만으로 해시를 다시 계산할 수 있게 한다.

| 해시 | 표시 | 단위 | 쓰임 |
| --- | --- | --- | --- |
| 구성 버전 | `cfg-…` | arm(생성 모델)마다 | 같은 조건의 생성인가 |
| 채점 버전 | `jdg-…` | 판정 묶음마다 | 점수를 나란히 놓을 수 있나 |
| 문항 세트 버전 | `qs-…` | 문항 묶음마다 | 같은 시험인가 |
| 실행 묶음 해시 | `run-…` | 실행마다(생성 쪽만) | 이어서 돌기(U6) |

이 단위가 끝나면 아래가 된다.

- `ragexp config check <yaml>`이 실행 전 검사를 하고 위 해시를 출력한다.
- 바뀌어도 같은 실험인 것은 해시를 바꾸지 않는다: 주소·키·meta·실행 설정·주석·키 순서·CRLF·arm 이름과 순서·판정 ID와 순서
- 결과를 바꾸는 것은 해시를 바꾼다: 모델·revision·파라미터·프롬프트 내용·level·부품 version

U2는 U3·U4와 나란히 진행된다. 실제 부품이 아직 없으므로, 시험은 가짜 부품(시험용 레지스트리)으로 한다.

## 사용자가 정해 달라고 한 5가지와 제안

### 1) 해시 정규화

**무엇을 해시하나: 부품 fingerprint와 프레임워크가 보장하는 공통 값만.**
- YAML 원문은 해시하지 않는다.
- 부품 fingerprint는 U1의 `component_fingerprint`이고, type·version·출력에 영향 주는 값이 들어간다.
- 공통 값은 `scheme`, `level`, 프롬프트 내용 해시다.
- 실행 설정(동시 처리 수·시간 제한·재시도)은 아래 4절의 `run` 칸에 따로 두므로 해시에 들어갈 길이 없다.

**기본값: 채운 뒤 해시한다**(effective value).
- 이유는 재현성이다. 사용자가 적은 값만 해시하면, 기본값이 바뀌어 결과가 달라져도 해시가 그대로다.
- 해시가 쓸데없이 바뀌는 것은 규칙 두 개로 막는다.
  - **`None`만 fingerprint에서 뺀다**(`drop_none`). 새로 더하는 선택 칸은 기본값 `None`으로 두면 기존 해시가 그대로다.
  - **`None`이 아닌 기본값(False·0·`[]`·`""` 등)을 가진 칸을 새로 더하거나, 기본값·동작을 바꾸면 부품 `version`을 올린다.** 해시가 바뀌는 것이 맞는 경우다.
- 시험으로 고정한다: 기본값을 직접 적어도 해시가 같다. `revision`이 없을 때와 `revision: null`일 때 해시가 같다.

**`level`: 넣는다.**
- **R0는 `generation_only`만 받는다.** `retrieval_only`·`full`은 "R2 이후 지원" 오류로 막는다. 아래 표는 문서로만 둔다.

| level | 쓰는 부품 | 지원 |
| --- | --- | --- |
| `generation_only` | corpus, chunker, retriever(`needs_gold`), generators | R0 |
| `retrieval_only` | corpus, chunker, embedder, vector_store, retriever, reranker | R2 |
| `full` | 모두 | R2 |

**안 쓰는 부품**(generation_only의 embedder 등):
- 이름만 확인한다. 등록되지 않은 type이면 오류로 멈춘다(설계 §5).
- 경고를 내고, 만들지 않고, 해시하지 않고, 그 안의 `${VAR}`도 확인하지 않는다.
- 같은 YAML의 level만 바꿔 쓸 수 있게 하려는 것이다.

**프레임워크 버전: 넣지 않는다.**
- `versions.json`에 기록만 한다.
- 정규화 규칙 자체가 바뀌면 **해시 규칙 버전 `scheme: 1`**을 올린다.

**정규 JSON 규칙**(`canonical_json`):
- 키는 정렬하고, UTF-8로 쓰고, 구분자에 공백을 넣지 않는다. `allow_nan=False`
- **정수로 떨어지는 float는 int로 바꾼다**(`0.0`→`0`). bool은 그대로다.
- 해시는 sha256이다. 표시는 `cfg-<앞 12자리>`로 한다.

### 2) arm별 구성 버전과 실행 묶음 해시

```text
arm 구성 버전 = H({ scheme, level,
                    parts: {corpus, chunker, retriever},     # level이 쓰는 공통 부품의 fingerprint
                    prompt_sha256,                             # 프레임워크가 보장(아래 "프롬프트")
                    generator: 그 arm의 generator fingerprint })

실행 묶음 해시 = H({ scheme, arms: {arm 이름: arm 구성 버전},
                    question_set: 문항 세트 버전, repeats })   # 채점 버전은 넣지 않음
```

- **arm 이름은 구성 버전에 넣지 않는다.** 이름만 바꿔도 같은 실험이다.
- 실행 묶음 해시에는 이름을 넣는다. 결과 표의 열 이름이 바뀌기 때문이다.
- generator를 더해도 **기존 arm의 구성 버전은 그대로**이고, 실행 묶음 해시만 바뀐다(시험).
- **실행 묶음 해시에 채점 버전을 넣지 않는다.** 설계 §8.1처럼 한 실행 안에 `judgments/<채점 버전>.jsonl`을 여러 개 둘 수 있어야 하기 때문이다(다시 채점). 판정만 바꿔도 실행 묶음은 그대로이므로, U6의 이어서 돌기가 끊기지 않는다(시험).
- 두 arm의 구성 버전이 같으면 경고한다(같은 설정을 두 번 적음).

### 3) `${VAR}`와 주소

**접속 칸**: `${VAR}`를 쓸 수 있는 칸. 목록을 따로 명시한다(`config.CONNECTION_FIELDS`).
- 정확한 이름: `base_url`, `api_base`, `endpoint`, `url`, `host`, `hostname`, `api_key`, `apikey`, `access_token`, `auth_token`, `token`, `key`, `secret`, `password`, `oc`
- 끝말: `_url`, `_key`, `_token`, `_secret`, `_password`
- 접두어: `auth`(`authorization`, `auth_header` …). 구현 검토 때 더했다.
- 이름 비교는 대소문자를 무시하고 하이픈을 밑줄로 바꿔서 한다.
- **meta 칸은 접속 칸이 아니다.** 부품이 `fingerprint_allow`로 연 이름(예: `stop_token`)도 접속 칸이 아니다. 그래서 이 검사는 `registry.get` **뒤**에 한다.

**규칙**:

| 규칙 | 내용 |
| --- | --- |
| `${VAR}` 위치 | 접속 칸에만 쓴다. 다른 칸(예: `model: ${MODEL}`)에 쓰면 오류다. YAML만 보고 조건을 알 수 있어야 하기 때문이다(설계 §2). |
| 접속 칸 값 | `${VAR}`만 쓴다. 리터럴(`http://localhost:8000`, `sk-…`)은 **거부하고 마스킹하지 않는다.** |
| 주소 직접 기재 | 값·**매핑 키**·**주석** 어디든 주소(URL·IPv4·호스트:포트)가 있으면 거부한다. meta도 예외가 아니다. |
| 주석 속 비밀값 | 주석에 `접속칸: 값` 꼴로 `${VAR}`가 아닌 값이 있으면 거부한다(예: `# api_key: sk-…`). |
| 환경 변수 | 정의되지 않았거나 비어 있으면 오류다. 메시지에는 **변수 이름만** 넣는다. |
| 문법 | `${NAME}`(대문자·숫자·밑줄)만 쓴다. 기본값 문법(`${X:-y}`)은 지원하지 않는다. |

- 주석 검사는 `raw_text`(주석 포함 원문)를 **줄의 토큰 단위로** 한다. U1의 `_HOST_PORT_RE`는 문자열 전체와 맞추는 식이므로 토큰마다 적용한다.
- **치환 전 원문 보존**: 위 검사를 통과한 `raw_text`만 U6이 `runs/<id>/config.yaml`에 쓴다. 그래서 주석에 있던 주소·키가 실행 기록에 남지 않는다.
- **치환 값이 새지 않게 한다.**
  - 접속 칸은 `SecretStr`로 받는다(repr·`str()`이 `**********`).
  - 거부 메시지에는 칸 경로만 넣고 값은 되풀이하지 않는다.
  - YAML 파싱 오류는 줄·칸 번호만 남기고 원문 조각은 버린다.
  - CLI는 `pretty_exceptions_show_locals=False`를 명시한다. 0.29.1의 기본값도 False지만, 기본값이 바뀌는 경우를 막는다.

**비밀값 없이 해시 보기**: `ragexp config check --no-env`
- 정의되지 않은 접속 변수를 자리표시 값으로 채워 해시만 계산한다. 접속 값은 해시에 들어가지 않으므로 결과가 같다.
- CI·다른 PC에서 쓸 수 있다. 자리표시 값은 메모리에만 있다.

### 4) `revision` 선택 칸, 실행 설정 칸

- **`revision: str | None = None`**: 생성·판정 모델 공통 설정 `ModelSettings`에 둔다. embedder·reranker도 같은 바탕을 쓴다(R2).
  - 값이 있을 때만 fingerprint에 넣는다(`drop_none`). 사용자가 적은 값을 그대로 기록하고, 서버에서 확인하지 않는다.
  - 응답 모델 이름은 설정과 같은지 확인만 한다(U3). 경로·주소 값은 U1 규칙으로 거부된다.
- **실행 설정 `run`**(해시 밖, U3·U6이 읽음):
  - generator·judge 항목의 예약 칸: `run: {concurrency: int ≥1 = 4, timeout_s: float > 0 = 180, max_retries: int ≥ 0 = 2}`
  - 최상위 칸: `run: {invalid_ratio_max: float 0~1 = 0.05}`. 실행 무효 상한이다(설계 §7.1).
  - 부품 생성자에는 넘기지 않는다. `LoadedConfig`에 arm별·판정별로 담아 U3(시간 제한·재시도)와 U6(동시 처리 수·무효 상한)에 넘긴다.
  - 기본값은 U3·U6 메모에서 조정할 수 있다.

### 5) 문항 세트 버전과 채점 버전의 경계

**문항 세트 버전**:
- 계산 함수 `question_set_version_for(questions)`는 U2 `versioning.py`에 둔다(구현 이름).
  - 각 `Question`을 `model_dump(mode="json", exclude_defaults=True)`로 바꾼다. 기본값(빈 칸)을 빼므로, R3에서 칸이 늘어도 기존 해시가 그대로다.
  - 이것을 정규 JSON으로 만들어 **qid 순으로 정렬**해 해시한다. 파일의 줄 순서·공백·키 순서·CRLF는 영향이 없다.
  - 중복 qid는 오류다. `provenance`는 들어간다.
- 파일 읽기는 **`src/ragexp/datasets/questions.py`의 `load_questions(path)` 한 곳**에서 한다. U2는 JSONL → `Question` 파싱만 하고, **U5가 같은 파일에** 스냅샷 대조 같은 내용 검증을 더한다. 로더는 하나다.

**채점 버전**(U2는 자리와 판정 목록 해시까지, 판정 동작은 **U7**):

```text
채점 버전 = H({ scheme,
               rules: [코드 규칙 판정 fingerprint …]   # 정규 JSON으로 정렬. ID·YAML 순서는 영향 없음
               primary: 주 판정의 fingerprint,
               merge: {method: primary_only} })      # 합치는 규칙(R4에서 교차 판정)
# 점검 문항(U7)·합격선(R4)은 그 단위에서 더한다. 보조 판정은 넣지 않는다(승인 결정 6).
```

- **판정 ID는 넣지 않는다**(arm 이름과 같은 정책).
- ~~보조 판정은 넣는다.~~ → **보조 판정은 넣지 않는다**(승인 결정 6). `Versions.secondary_judges`에 판정 ID별 type·fingerprint·해시로 따로 기록한다.
- **판정 ID**: YAML의 `id`이고, 없으면 `type`을 쓴다. 같은 type이 둘 이상이면 `id`가 필수다. 판정마다 `role`(primary·rules·secondary, 기본 secondary)을 두고, 주 판정은 정확히 하나다.
- **`Verdict.judge_id` 채우기**(U7 경계): 판정 부품은 ID를 모른다. U7 채점기가 `verdict.model_copy(update={"judge_id": …, "judge_type": …})`로 붙인다(U1의 `model_copy`는 다시 검증한다). ID를 부품 설정에 넣지 않으므로 fingerprint에도 들어가지 않는다.
- 채점 버전에는 생성 쪽 설정이 없다. 구성 버전에는 판정 쪽이 없다. 판정만 바꾸면 구성 버전·실행 묶음 해시는 그대로이고 채점 버전만 바뀐다(시험).

### 프롬프트 (U5 경계)

- top-level `prompt` 파일을 읽어 LF·BOM을 정규화한 텍스트와 sha256을 `LoadedConfig.prompt`에 둔다. 경로는 해시 밖이다.
- **전달**: 로더가 generator를 만들 때 예약 칸 `prompt_template`(텍스트)를 설정에 넣어 준다. YAML에서 사용자가 이 칸을 쓰면 오류다.
- **해시**: `prompt_sha256`은 프레임워크가 arm 구성 버전에 직접 넣는다(보장). generator fingerprint에 같은 해시가 또 들어가도 결과가 달라지지 않는다.
- **렌더링 코드**(근거 [1]..[n]을 끼워 넣는 U5 `prompts.py`): 바뀌면 이를 쓰는 generator의 `version`을 올린다.

### 실행 기록만으로 다시 계산하기 (U6 경계)

- 해시마다 **원재료**(정규 JSON으로 만들기 전 객체: 부품 fingerprint, prompt_sha256, level, scheme …)를 `Versions.preimages`에 함께 둔다. U6이 `versions.json`에 쓴다.
- `verify_versions(versions)`는 원재료만 받아 해시를 다시 계산해 대조한다. 환경 변수·원본 파일·부품 인스턴스가 필요 없다(설계 §8.1 "파일에서 다시 만들 수 있다").
- 원재료에는 주소·키가 없다. fingerprint 규칙으로 이미 걸러진 값이다.
- 비교 화면(R1)의 "구성 차이(바뀐 칸만)"도 이 원재료끼리 비교한다.

## 만들 것

### 1) 구성 스키마와 읽기 (`src/ragexp/config.py`)

**YAML 로더**: PyYAML `SafeLoader`를 확장한다. 새 의존성이고 ADR 0002로 남긴다.
- 중복 키는 오류다.
- 날짜 자동 변환을 끈다(문자열로 읽음).
- JSON 값이 아닌 태그는 오류다.
- 파싱 오류는 줄·칸 번호만 남긴다.

**스키마**(pydantic):

| 칸 | 타입 | 해시 |
| --- | --- | --- |
| `name` | str | ✗ |
| `level` | `generation_only`(R0) | ✓ |
| `corpus`·`chunker`·`retriever` | `ComponentSpec` | fingerprint |
| `embedder`·`vector_store`·`reranker` | `ComponentSpec \| None` | level이 쓸 때만 |
| `generators` | `{arm 이름: GeneratorSpec}` (1개 이상, arm 이름 `^[A-Za-z0-9_-]+$`) | arm마다 |
| `prompt` | YAML 기준 상대 경로 | 내용 sha256 |
| `judges` | `list[JudgeSpec]` (1개 이상) | 채점 버전 |
| `questions` | YAML 기준 상대 경로 | 문항 세트 버전 |
| `repeats` | int ≥ 1 | 실행 묶음 |
| `run` | `{invalid_ratio_max}` | ✗ |

- 최상위는 `extra="forbid"`이고, 빈 값(`null`, `""`)은 거부한다.

**부품 항목**(`ComponentSpec`, `extra="allow"`. 예약 칸을 뺀 나머지는 부품 설정):

| 예약 칸 | 어디에 | 처리 |
| --- | --- | --- |
| `type` | 모두 | 등록 이름 |
| `meta` | 모두 | `ModelMeta`. 해시 밖, U8 비용용. 판정 meta도 담는다 |
| `run` | generator·judge | 실행 설정(4절) |
| `id`, `role` | judge | 판정 ID·역할(primary·rules·secondary) |
| `prompt_template` | generator | 로더만 넣는다. YAML에 있으면 오류 |
| `prompt` | generator만 | arm별 프롬프트는 R4. 다른 부품에서는 일반 설정 칸 |

- 예약 칸은 부품 설정으로 넘기지 않는다. 그래서 부품 설정 칸 이름으로 쓸 수 없다.

**`ModelMeta`**(설계 §4의 칸만, 그 밖의 키는 거부):
- `price_per_1m_input`, `price_per_1m_output`, `gpu_cost_per_hour`: float ≥ 0
- `vram_gb`: float > 0
- `license`: str
- `deploy`: `cloud`·`on_prem`
- `air_gapped`: bool
- `end_of_life`: 날짜 문자열

**`ModelSettings`**(U3·U7이 `config_model`로 상속):
- `model: str`
- `revision: str | None = None`
- `params: dict = {}`
- `base_url: SecretStr`, `api_key: SecretStr | None = None`
- `fingerprint_items()`: model·revision·params에 `drop_none`을 적용한 값

**`load_config(path, registry, *, env=os.environ, allow_missing_env=False) -> LoadedConfig`** 순서:
1. 원문을 읽는다.
2. 원문을 줄·토큰 단위로 검사한다(주소, 주석 속 비밀값).
3. YAML을 파싱하고, 최상위 스키마를 검증한다(R0 level 포함).
4. level이 쓰는 부품과 안 쓰는 부품을 가른다. 쓰는 부품은 `registry.get`, 안 쓰는 부품은 이름만 확인한다(경고).
5. level과 검색기 짝을 검사한다(generation_only이면 `needs_gold=True`).
6. 쓰는 부품의 값·키를 검사한다: `${VAR}` 위치, 접속 칸 리터럴, 주소. 접속 칸 판정에는 부품의 `fingerprint_allow`를 반영한다.
7. 프롬프트를 읽는다.
8. 환경 변수를 치환한다.
9. 부품을 만든다(`registry.create`). `config_model` 검증은 **여기서 한 번만** 한다(치환 뒤).
10. `LoadedConfig`를 돌려준다.

`LoadedConfig`에 담는 것:
- `raw_text`
- 파싱된 원문(치환 전)
- 부품 인스턴스, arm별·판정별 meta와 run
- 판정 목록(ID·주 판정)
- 프롬프트 텍스트와 sha
- 문항 경로
- 경고

**레지스트리 `create` 연결**(U1 약속 확정, `registry.py` 수정):
- `config_model`이 있으면 `model_validate(config)`로 검증한 뒤 `cls(validated)`로 만든다.
- 없으면 `cls(**config)`다.
- 검증 오류는 **칸 위치와 오류 종류(`loc`·`type`)만** 담는다. 입력값은 넣지 않는다.

## 결정 필요

1. **기본값 처리**: effective value로 해시하고, `None`만 빼는 것을 제안한다. 그 밖의 기본값을 바꾸거나 새 칸을 더하면 부품 `version`을 올린다.
2. **`${VAR}` 허용 범위**: 접속 칸에만 허용하는 것을 제안한다(3절 명시 목록).
3. **주소 거부 범위**: meta와 주석까지 모두 거부하는 것을 제안한다. 모델 카드 링크 같은 예외가 필요하면 알려 주세요.
4. **YAML 라이브러리**: PyYAML 6.0.3(MIT)을 런타임 의존성으로, types-PyYAML을 dev 의존성으로 추가하는 것을 제안한다. 대안 ruamel.yaml은 주석 보존이 장점이지만 U2에는 필요 없다.
5. **프롬프트**: top-level 하나를 모든 arm이 같이 쓰고, 로더가 `prompt_template`로 주입하는 것을 제안한다. arm별 프롬프트는 R4에서 다룬다.
6. ~~보조 판정을 채점 버전에 넣기~~ → 넣지 않음(승인 결정 6).
7. **`run` 기본값**: 동시 처리 4·시간 제한 **180초**(승인 결정 7)·재시도 2, 실행 무효 상한 5%.
8. **크기**: M에서 **L(2일)**로 바꾸는 것을 제안한다.
9. **변형(base + variants) YAML**: R2로 미루는 것을 제안한다.

| 안 쓰는 부품 동작 | 이름만 확인하고 경고, `${VAR}`는 확인하지 않음 |
| 판정 ID 정책·`judge_id` 채우기 | ID는 해시에서 뺐다. U7이 `model_copy`로 붙인다. 보조 판정을 넣는 이유를 적었다 |
| `drop_none`의 "중립값"이 모호 | None만 뺀다고 정리했다 |
| 문항 세트가 설계와 다름 | "설계와 다른 점"에 적고 `exclude_defaults`를 쓴다 |
| 완료 기준 2가 모순 | 표로 다시 적었다 |
| `ComponentSpec` extra·예약 칸·검증 순서 | `extra="allow"`, 예약 칸 표, `config_model` 검증은 치환 뒤 한 번 |
| 판정 meta | `LoadedConfig`에 판정별 meta를 담는다 |

확인 필요 4건:
- Typer 0.29.1의 `pretty_exceptions_show_locals` 기본값이 False임을 확인했다. 그래도 명시한다.
- U4 법령 수집: 주소는 코드에 고정하고 OC는 환경 변수로 받는다. YAML에는 주소가 없다. 이 약속은 U2 구현 때 R0.md "정해 둔 방향"에 적어 U4 메모로 넘긴다.
- YAML 위치는 칸 경로로, 파싱 오류는 줄 번호로 알린다.
- 비밀값 없는 환경을 위해 `--no-env`를 둔다.

## 구현 검토 (design-reviewer, 2026-11-17) — 모두 반영함

아래는 받은 지적 원문 요약이다. 반영 내용은 "결과" 절의 표에 있다.

**높음**
1. **원문 검사가 문장 속 주소를 놓친다**
   - 놓치는 예: `gpu-01:8000에서`(조사), `gpu-01:8000.`, `localhost:8000;`, `--host=gpu-01:8000`, `10.0.0.5.`(문장 마침표)
   - 원인: 토큰 단위의 `^…$` 정규식이다.
   - 고칠 방향: 줄 전체를 search형 정규식으로 검사하고, 위 예시를 `ADDRESS_TEXTS`에 더한다.
2. **안 쓰는 부품은 값을 검사하지 않는다**
   - generation_only의 `embedder: {api_key: sk-…}`가 통과해 raw_text에 남는다.
   - 고칠 방향: 접속 칸 리터럴·주소·빈 값 검사는 하고, `${VAR}` 확인만 건너뛴다(allow는 빈 집합).

**중간**
3. `drop_none`이 ModelSettings에만 적용된다. 모든 fingerprint에 적용해야 한다(`component_fingerprint` 또는 `compute_versions`). 리스트 안의 dict도 포함한다.
4. 중첩 접속 칸(`params.extra_headers.x_api_key: ${K}`)과 config_model이 없는 부품은 치환 값이 일반 문자열로 남아 repr에 보인다.
   - 고칠 방향: `${VAR}`를 부품 설정 맨 위 접속 칸에만 허용한다.
5. `auth*`(`Authorization: Bearer …`)가 접속 칸이 아니다.
   - 고칠 방향: 접속 칸에 `auth*` 접두어를 더한다. `Bearer`·`sk-` 같은 비밀값 꼴 거부는 결정이 필요하다.
6. 판정 `role`을 빠뜨리면 secondary가 되어, 코드 규칙 판정이 채점 버전에서 조용히 빠진다. LLM 판정에 `role: rules`를 적어도 막지 못한다.
   - 고칠 방향: 판정 클래스가 성격(code·llm)을 밝히고 role과 대조한다. 또는 role을 필수로 한다.
7. CLI가 FingerprintError(경로형 모델 이름 등)·UnicodeDecodeError를 잡지 않아 traceback이 나오고 `--json`이 깨진다.
   - 고칠 방향: 칸 경로를 붙인 오류로 감싸고 CLI 시험을 더한다.
8. 빠진 시험:
   - config_model 경로의 생성자 예외 마스킹
   - 검증이 치환 뒤 한 번만 일어나는지
   - `load_config`가 `fingerprint_allow`를 반영하는지(가짜 부품 필요)
   - 한 arm만의 generator version, 주 판정 version
   - 코드 규칙 판정 추가·삭제와 순서
   - 안 쓰는 부품을 더해도 해시가 그대로인지

**낮음**
9. `prompt`가 모든 부품의 예약 칸이 됐다. generator에서만 막아야 한다(U7 판정 템플릿 칸과 충돌).
10. 접속 칸 목록이 `FORBIDDEN_NAMES - meta`로 만들어져 메모의 명시 목록과 다르다(`server`, `address` 포함). 명시하거나 메모를 고친다.
11. versioning 함수 이름이 메모와 다르다(`question_set_version_for`, `compute_versions`). 메모를 고친다.
12. design.md §5 머리 문장("YAML과 fingerprint를 합쳐")이 새 규칙과 모순된다. §6.3은 고치지 않았다.
13. BOM이 있는 파일은 raw_text가 원문과 바이트 단위로 다르다. `raw_bytes`를 보관하거나 기준을 고친다. U6 쓰기 방식(바이트, `newline=""`)도 정한다.
14. 로더가 모든 generator에 `prompt_template`을 넣는다는 약속을 protocols.py·§4에 적어야 한다.
15. 주석 속 `접속칸: 값` 검사:
    - 미탐: 아포스트로피·이스케이프가 있으면 주석을 못 찾는다.
    - 오탐: `# key: 정렬 기준`
16. `verify_versions`가 `Versions.scheme`과 원재료의 `scheme`이 같은지 보지 않는다.
17. YAML 1.1에서 `1e-3`이 문자열로 읽힌다. float resolver를 YAML 1.2식으로 바꾸거나 ADR에 함정으로 적는다.

**확인 필요** (다음 단위로 넘김)
- U3 config_model이 `base_url`을 URL 형식으로 검증하면 `--no-env` 자리표시 값과 충돌한다.
- U7 판정 템플릿 칸 이름(9와 연결)
- 코드 규칙 판정 지표를 U8에서 점수로 쓰는지(6과 연결)
- U6이 raw_text를 쓰는 방식(13과 연결)

1번 반영(문장 속 주소):
- `has_address`를 문자열 어디서든 찾는 방식으로 바꿨다. 원문 검사는 줄 전체를 본다.
- 문장 속 주소, 조사·마침표·세미콜론·`=`가 붙은 주소, 문장 끝 IPv4를 잡는다.
- 모델 태그(`qwen3:32b`)·시각(`12:30`)·비율·조문 ID는 통과한다.

4번 반영(중첩 접속 칸):
- 접속 칸은 부품 설정 맨 위에만 둔다.
- 접속 칸을 받는 부품은 `config_model`에서 그 칸을 `SecretStr`로 선언해야 한다.

6번 반영(판정 role):
- `role`을 필수로 했다.
- 판정 부품이 `judge_kind`(code·model)를 밝히면 대조한다. code는 rules만, model은 rules가 될 수 없다.

7번 반영(CLI traceback):
- `load_config` 마지막에 fingerprint를 미리 검사한다. 경로형 모델 이름 오류가 칸 경로·`--served-model-name` 안내와 함께 `ConfigError`로 나온다.
- CLI는 ValueError 계열을 모두 오류 출력으로 처리한다. UTF-8이 아닌 파일도 마찬가지다.

13번 반영(BOM):
- `LoadedConfig.raw_bytes`에 원문 바이트를 그대로 보관한다. `raw_text`는 BOM을 뺀 텍스트다.
- U6은 `raw_bytes`를 바이트로 쓴다.

### 설계와 달라진 점 (메모 이후)

- 판정 항목의 `primary: true` 대신 `role`(필수)을 둔다(승인 결정 6 때문).
- 판정 부품의 선택 속성 `judge_kind`, 생성기의 `prompt_template` 약속, 접속 칸의 `SecretStr` 약속을 둔다(design.md §4).
- 원문 검사에 흔한 비밀값 꼴을 더한다. `Bearer`·`sk-`·`hf_`는 구현 검토 때 넣었고, 승인 뒤 `ghp_`·`github_pat_`·`AKIA`·`AIza`를 더했다(모두 7가지, `fingerprint.SECRET_PATTERNS`).
- 하네스: 편집 훅(`ruff_on_edit.py`)이 안 쓰는 import(F401)를 지우지 않고 알리기만 하게 바꿨다. 여러 번에 나눠 고치는 중간에 아직 쓰기 전인 import가 지워지는 일이 실제로 있었다.

### 남은 일 (다음 단위)

- **U3**: `openai_compat`의 `config_model`이 `base_url`을 URL 형식으로 검증하면, `--no-env` 자리표시 값(`__ragexp_unset__`)이 실패한다. U3 메모에서 정한다(예: URL 형식 검사는 실제 호출 때).
- **U6**:
  - 실행 기록 `config.yaml`은 `raw_bytes`를 바이트 그대로 쓴다(`newline` 변환 없음).
  - `versions.json`에는 `Versions.to_dict()`를 쓴다.
  - 플러그인 오류 메시지의 경로 문제(U1 남은 일)도 이어서 본다.
- **U7**:
  - 판정 템플릿 칸 이름을 정한다(`prompt`는 판정에서 쓸 수 있다).
  - `judge_kind`를 실제 판정에 선언한다.
  - 코드 규칙 지표를 U8에서 점수로 쓸지 정한다.
  - 점검 문항을 채점 버전에 넣을지 정한다.
- **R4**: arm별 프롬프트, 교차 판정(합치기 규칙)
- **YAML 1.1 bool 함정**(`on`/`off`): 스키마가 막는 칸만 안전하다. 부품 설정의 자유 칸(params)에는 bool로 들어갈 수 있다. 실제 문제가 생기면 다시 본다.

### 승인 뒤 결정 (2026-11-17)

- **기본값 두 가지는 그대로 둔다.** 비밀값 꼴은 원문 어디서든 거부하고, 판정 `role`은 필수이며 `judge_kind`와 대조한다.
- **비밀값 꼴 추가**: `ghp_`, `github_pat_`, `AKIA`, `AIza`. 시험은 `test_secret_patterns_*`와 `test_addresses_rejected_anywhere` 4가지다. 시험 값은 gitleaks에 걸리지 않도록 실행할 때 이어 붙여 만든다.
- **주소·비밀값 검사는 지금 수준에서 확정한다.**
  - 새 패턴은 실제로 새는 사례가 나왔을 때만 더한다. 그 밖은 design.md §5 "알려진 남는 위험"에 적는다. 두 번째 겹은 gitleaks(커밋마다)와 CI 전체 이력 검사다.
  - `test_secret_pattern_list_is_closed`가 목록 크기를 고정한다.
  - design-reviewer 점검 목록 10번에 "검사 패턴 확장은 실제 사례가 있을 때만"을 넣었다.
- **pytest 경고**: 한 번 "warning 1건"이 나왔지만, `-rw`로 세 번 다시 돌렸을 때는 재현되지 않았다. 원인은 확인하지 못했다(U1 때도 한 번 있었음).
