# U0 레포 뼈대·작업 하네스·설계 문서 정리

상태: 로컬 완료, CI 확인 대기 (push 승인 필요)
관련: docs/design.md §9, §10 · docs/units/R0.md

## 목표

R0 단위들이 같은 규칙으로 돌아갈 바닥을 깐다. 이 단위가 끝나면 다음 상태가 된다.

- 패키지 `ragexp`가 설치·시험·린트된다.
- 비밀값 검사가 로컬(pre-commit, Claude 훅)과 CI 양쪽에서 돈다.
- Claude Code 작업 하네스(규칙·권한·훅·명령·설계검토 에이전트)가 준비된다.
- 설계 문서가 이번에 내린 결정과 맞는다.

## 완료 기준

1. `uv sync --locked && uv run pytest && uv run ruff check && uv run ruff format --check && uv run mypy src`가 로컬에서 통과한다.
2. `uv run ragexp --help`, `uv run ragexp --version`이 동작한다.
3. `uv run pre-commit run --all-files`가 통과한다.
4. 가짜 키를 넣은 임시 파일을 스테이징하면 pre-commit gitleaks와 Claude 훅이 둘 다 막는다(확인 뒤 되돌림).
5. examples/에 가짜 실제 주소를 넣으면 `no-real-urls`가 실패한다(확인 뒤 되돌림).
6. `.py` 파일을 편집하면 훅이 포맷한다. `.env` 쓰기는 막힌다.
7. design.md가 위 1)의 항목을 모두 반영하고, 옛 이름 `ref`(패키지·CLI)가 남아 있지 않다(grep).
8. (push 승인 뒤) CI lint·test(4조합)·secrets가 모두 초록이다.

### 설계와 달라진 점

- `.env` 훅의 이름과 범위: `block_env_write.py` 대신 `block_env_access.py`로 만들었다. 쓰기뿐 아니라 Read도 막는다. 권한 deny 규칙은 `.env.example`을 예외로 둘 수 없어서 훅으로 처리했다.
- ruff의 markdown 포맷: ruff 0.17은 markdown 속 코드 블록도 포맷한다. 설계 문서의 예시 코드를 건드리지 않도록 `extend-exclude = ["*.md"]`를 넣었다.
- ruff 훅 순서: `check --fix` → `format` → `check`로 했다. format을 먼저 하면 import를 지운 자리에 빈 줄이 남는다.
- gitleaks pre-commit 훅: `pass_filenames: false`를 넣었다. 파일 이름을 인자로 넘기면 `gitleaks git`이 오류를 낸다.
- 커밋 감지: `git commit-tree`는 커밋으로 보지 않는다(`commit(?![\w-])`).
- 권한 목록 추가: `git show`, `uv lock --check`(allow), `uv remove`, `gh pr create`(ask), `git push -f`(deny).

### 남은 일

- CI 첫 실행 결과 확인(기준 8). Windows에서 3.14로 도는지도 이때 확인한다.
- Bash로 `.env`를 읽는 것(예: `cat .env`)은 권한·훅이 막지 못한다. CLAUDE.md 규칙으로만 막는다.
- `git commit -a`처럼 커밋할 때 스테이징하는 경우, Claude 훅의 staged 검사가 그 변경을 보지 못한다. pre-commit 훅이 다시 검사하므로 이중 장치 중 하나만 동작한다.
- `docs/adr/`는 첫 런타임 의존성을 추가할 때 만든다(typer는 설계 §9.1에 이미 정해짐).
