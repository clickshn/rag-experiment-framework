# U3 모델 호출 통로

상태: 구현 완료 (2026-11-17, 검사 통과·프록시 결정 반영, PR #4)
관련: docs/design.md §4 "모델 호출 통로", §5, §7.1, §8.1 · docs/units/R0.md · docs/units/U2.md "남은 일" · 브랜치 `u3-model-client`

## 목표

모든 모델 호출(R0는 생성·LLM 판정의 chat)이 지나는 **한 곳**을 만든다(설계 §4). 이 단위가 끝나면 아래가 된다.

- OpenAI 호환 `/chat/completions`를 httpx로 부르고, 결과를 U1의 `Answer`로 돌려준다(본문·finish_reason·usage·served_model·오류 종류·시도 횟수·경고).
- 시간 제한·재시도·토큰·지연 기록·응답 모델 이름 확인·잘림 구분을 여기서만 한다.
- 주소·키·응답 본문은 오류 문구·경고·예외 어디에도 나가지 않는다.
- 모든 시험은 네트워크 없이 돈다(httpx `MockTransport`, 표준 라이브러리 가짜 서버).

**R0 범위**: chat만 만든다. embeddings·rerank 호출은 R2로 미룬다. 생성기 부품(`openai_compat` Generator)은 U5, LLM 판정 부품은 U7이 이 클라이언트를 써서 만든다.

## 클라이언트를 누가·언제 만드나 (U5·U6·U7 경계)

| 항목 | 정한 것 |
| --- | --- |
| 실행 설정 전달 | 로더가 부품 설정에 **`run`을 주입**한다(`prompt_template`과 같은 방식). `ModelSettings`에 `run: RunSettings` 칸(기본값 있음)을 두고, 로더는 YAML의 `run`(없으면 기본값)을 넣는다. `run`은 `fingerprint_items()`에 들어가지 않는다(해시 밖, U2 원칙 그대로). `config_model`에 `run` 칸이 없는 부품(코드 규칙 판정 등)에는 주입하지 않는다. |
| 클라이언트 생성 시점 | 부품은 생성자에서 클라이언트를 만들지 **않는다**. **처음 호출할 때 늦게** 만든다(`ChatClient(settings)`). 그래서 `config check --no-env`(자리표시 값)는 부품을 만들고 해시를 낼 수 있다. |
| 자리표시 값 거부 | `ChatClient`를 만들 때 `base_url`·`api_key`가 자리표시 값이면 오류를 낸다. 늦게 만드므로 실제 호출 직전에 걸린다. |
| 경고 전달 | 클라이언트는 `Answer` 하나를 돌려주고, 경고는 **`Answer.warnings`**(새 칸)에 담는다. 생성기는 이 `Answer`를 그대로 돌려준다(U5 약속). U6이 실행 기록에 쓰고, U8이 같은 경고를 한 번만 모아 보여 준다. |
| 판정 쪽 | LLM 판정 호출의 두 번째 층(실행 단위 재실행·무효 판단), `Verdict`에 실패 종류·served_model·경고를 남기는 방법은 **U7**이 정한다(U3는 클라이언트만 준다). |

이 약속은 design.md §4 "부품이 지킬 약속"에 더한다.
- `run` 주입
- 클라이언트는 늦게 만든다
- 생성기는 클라이언트의 `Answer`를 그대로 돌려준다

## 넘어온 항목과 제안 (STATUS.md "남은 일 모음")

### 1) `base_url` 형식 검사와 `--no-env` 자리표시 값 충돌 (U2에서)

**형식 검사는 `ModelSettings`의 칸 검증기에서 하고, 자리표시 값만 통과시킨다.**
- 자리표시 값을 공개 상수 `config.UNSET_PLACEHOLDER`로 둔다(지금은 `_UNSET`).
- `base_url` 검증기:
  - 자리표시 값이면 통과한다.
  - 아니면 스킴이 `http`·`https`이고 호스트가 있는지 본다.
  - URL 안의 계정(`user:pw@`)·쿼리·조각(`#`)은 거부한다.
  - 끝의 `/` 하나는 떼어 정규화한다(`…/v1/`이 `…/v1//chat/completions`가 되지 않게).
- **환경 변수가 있으면 `config check` 단계(실행 전)에서 형식 오류를 잡는다.** `--no-env`면 해시만 낸다. 접속 값은 해시 밖이라 결과가 같다.
- 오류는 `PydanticCustomError("base_url_format", …)`로 낸다. 레지스트리는 칸 위치와 오류 종류만 보여 주므로(U2) 값은 나오지 않는다.
- `base_url`은 OpenAI SDK처럼 **`/v1`까지 포함한 주소**로 받는다. 클라이언트는 그 뒤에 `/chat/completions`만 붙이고 경로를 추측해 고치지 않는다.

### 2) 경로형 모델 이름 안내 확정

| 언제 | 무엇 | 동작 |
| --- | --- | --- |
| 구성을 읽을 때 | 설정 `model`이 절대 경로 | 이미 거부한다(U1·U2). 안내 문구도 있다. **확정만 한다.** |
| 응답을 받을 때 | 응답 `model`(served_model)이 절대 경로 | 불일치 경고에 같은 안내를 붙인다 |

- **경로 판정 기준**: U1 fingerprint의 **절대 경로 규칙 그대로**다(드라이브 문자, UNC, `~/`, `/이름/…`, 알려진 루트).
  - 이를 공개 함수 `fingerprint.is_absolute_path(value)`로 꺼내 둘이 같이 쓴다.
  - `Qwen/Qwen3-8B` 같은 HF 저장소 ID는 경로가 **아니다**(시험).
- **불일치 판정**: 설정 `model`과 응답 `model`의 **원래 값**을 정확히 비교한다(대소문자 구분).
  - 그래서 `/models/Qwen3-8B` ↔ `Qwen3-8B`도 불일치다.
  - 응답에 `model`이 없으면 `served_model=None`이고 경고하지 않는다.
- **기록**: 응답 모델 이름이 경로면 `Answer.served_model`과 **경고 문구 모두에** 마지막 경로 조각만 넣는다. 서버 경로에 사용자 이름 같은 개인 정보가 들어갈 수 있기 때문이다.
  - 경고 예: "응답 모델 이름이 경로입니다(…/Qwen3-8B). vLLM은 --served-model-name으로 이름을 정하세요. 모델 경로는 PC마다 달라 구성 버전에 넣지 않습니다"
  - 전체 경로는 어디에도 남지 않는다(시험).

### 3) revision 기록

- `revision`은 사용자가 적은 값 그대로 arm 구성 버전의 원재료(`versions.json`)에 이미 들어간다(U2). U3는 더 기록하지 않는다.
- **서버에서 확인하지 않는다.** OpenAI 호환 API에는 revision을 묻는 길이 없다. 확정만 한다.

### 4) 재시도 두 층과 실패 분류 셋 (승인 때 고침)

| 층 | 누가 | 언제 | 몇 번 | 대상 |
| --- | --- | --- | --- | --- |
| **호출 안 재시도** | U3 클라이언트 | 한 번의 호출 안에서, 대기 후 곧바로 | 아래 "시도 횟수" | 서버 사정 |
| **실행 단위 재실행** | U6 실행기(생성 항목) | 모든 항목을 한 번 돈 뒤, 실패한 항목만 | **한 번** | 호출 안 재시도를 다 쓰고도 서버 사정으로 실패한 것 |

판정 호출의 두 번째 층은 U7이 정한다.

**실패 분류 셋** (U6·U7이 쓴다. U6 확정 전에 여기 미리 적어 둔다):

| 분류 | 무엇 | 호출 안 재시도 | 실행에서(U6·U7) |
| --- | --- | --- | --- |
| **서버 사정** | `connect`·`timeout`·`http_status`(408·429·5xx)·`other` | 함 | 실행 단위 재실행 한 번. 그래도 남으면 실행 무효 비율에 센다 |
| **모델·문항 사정** | `client_error`(400·422 등), `parse`, 잘림(`finish_reason=length`, 오류 아님) | 안 함 | 항목 실패로 채점하고 건수를 따로 표시한다 |
| **설정 오류** | `config_error`(401·403·404) | 안 함 | 실행을 **바로 멈춘다**. 칸 경로와 원인만 안내하고 키 값은 넣지 않는다 |

- `other`를 서버 사정에 두는 이유: 모르는 오류가 조용히 오답으로 채점되지 않게 하려는 것이다. 남으면 실행 무효 쪽으로 드러난다.
- 클라이언트는 이 표를 `failure_class(answer) -> "server" | "item" | "config" | None`으로 낸다(정상 응답은 `None`). U6·U7은 이 함수만 보고 나눈다.

**httpx 예외·응답 → `error_kind` 대응표**:

| 일어난 일 | `error_kind` | 분류 | 최대 시도 |
| --- | --- | --- | --- |
| `httpx.TimeoutException` 4종(ConnectTimeout·ReadTimeout·WriteTimeout·PoolTimeout) | `timeout` | 서버 | **2번** |
| `httpx.NetworkError` 4종(ConnectError·ReadError·WriteError·CloseError) | `connect` | 서버 | 3번 |
| `httpx.RemoteProtocolError`(응답 중 서버가 연결을 끊음) | `connect` | 서버 | 3번 |
| HTTP 429 | `http_status` | 서버 | 3번, `Retry-After`를 따름 |
| HTTP 408·5xx | `http_status` | 서버 | 3번(`Retry-After`가 있으면 따름) |
| HTTP 401·403·404 | `config_error` (**새 값**) | 설정 | 1번 |
| HTTP 그 밖의 4xx(400·413·422 등) | `client_error` (**새 값**) | 모델·문항 | 1번 |
| 2xx인데 본문이 JSON이 아님, `choices`·`message` 없음 | `parse` | 모델·문항 | 1번 |
| 그 밖의 상태 코드(1xx·3xx. httpx는 리다이렉트를 따라가지 않음) | `other` | 서버 | 3번 |
| 그 밖의 `httpx.HTTPError`(LocalProtocolError·ProxyError·UnsupportedProtocol·DecodingError·TooManyRedirects) | `other` | 서버 | 3번 |
| `httpx.InvalidURL`(HTTPError 밖, 메시지에 호스트 값) | `config_error` | 설정 | 1번. 구성 검사(`base_url_format`)가 먼저 막고, 클라이언트는 검증을 건너뛴 설정에 대비해 잡는다(구현 검토 반영) |
| httpx 밖의 예외 | 잡지 않는다(코드 결함이므로 그대로 올라감) | — | — |

**시도 횟수**:
- 전체 시도는 `1 + run.max_retries`(기본 2라 3번)를 넘지 않는다. `max_retries=0`이면 한 번만 시도한다.
- 시간 초과는 그 안에서 **최대 2번**이다(코드 상수 `MAX_TIMEOUT_ATTEMPTS = 2`). 두 번째 시간 초과가 나면 남은 횟수가 있어도 멈춘다.
  - 이유: 시간 제한 180초에서 시간 초과를 세 번 되풀이하면 9분을 쓴다. 두 번 연속이면 서버가 밀려 있거나 출력이 너무 길다는 뜻이라, 더 해도 같을 가능성이 크다.
  - 설정 칸으로 열지 않는다. 필요해지면 `RunSettings`에 더한다(해시 밖이라 버전은 그대로).
- 시도마다 오류 종류가 달라도 된다(예: 503 → 시간 초과 → 성공). 두 규칙을 모두 센다.

**대기**:
- 기본은 1초 × 2^(시도−1), 최대 30초다. 첫 실패 뒤 1초, 두 번째 실패 뒤 2초.
- 재시도 대상 HTTP 응답에 `Retry-After`가 있으면 그 값을 쓴다(429가 대표). 상한은 60초다.
  - 숫자(초)면 그대로 쓴다.
  - HTTP 날짜 형식이면 그 시각까지 남은 초로 바꾼다. 이미 지났으면 0초다.
  - 읽을 수 없으면 기본 지수 대기로 간다.
- 지터는 넣지 않는다(결정성).
- 대기 함수(`sleep`), 시계(`clock`), 날짜 계산용 벽시계(`now`)를 주입할 수 있어서 시험은 기다리지 않는다.

**그 밖의 규칙**:
- **시간 제한**: `run.timeout_s`(기본 180초)를 응답을 기다리는 시간(read·write·pool)으로 쓴다. 연결 시간 제한은 10초로 고정한다.
- **잘림**: 정상 응답의 `finish_reason=length`는 오류가 아니다. 재시도하지 않고 `length`로 기록한다. 분류는 모델·문항 사정이다.
- **오류일 때 `Answer.text`**: 빈 문자열이다. 응답 본문을 넣지 않는다.
- **설정 오류 문구**: 칸 이름과 원인만 쓴다. 칸 경로의 앞부분(`generators.A`)은 클라이언트가 모르므로 U6이 멈출 때 붙인다.
  - 401: "HTTP 401 인증 실패: api_key 칸(환경 변수 값)을 확인하세요"
  - 403: "HTTP 403 권한 없음: api_key 칸의 권한을 확인하세요"
  - 404: "HTTP 404 찾지 못함: base_url 칸(/v1까지 포함)과 model 칸을 확인하세요"
- **`ErrorKind`에 `config_error`를 더한다** (승인 때 물은 것, 이렇게 정함):
  - U6이 `Answer` 하나만 보고 바로 멈출 수 있어야 한다. 상태 코드 칸을 따로 두면 판단 규칙이 U6에 흩어진다.
  - 예외로 던지지 않는다. 생성기·판정 Protocol은 `Answer`·`Verdict`를 돌려주는 한 길로 둔다. 다른 arm에서 돌던 항목을 어떻게 끝낼지는 U6이 정한다.

**지연** (승인 때 고침):
- `Usage.latency_ms`: **마지막 시도 한 번**의 시간이다. 대기와 앞선 실패 시도는 뺀다.
  - 성공이면 성공한 시도의 시간, 모두 실패면 마지막 실패 시도의 시간이다.
  - 속도 지표(p50·p95)는 `finish_reason ≠ error`인 것만 쓴다(U8).
- `Usage.total_ms`(**새 칸**, 선택): 첫 시도 시작부터 마지막 시도 끝까지다. 재시도와 대기를 포함한다.
  - U8 로컬 비용(벽시계 시간 × GPU 시간당 단가)의 재료다.
  - 동시 처리에서는 항목별 `total_ms`의 합이 실행 벽시계 시간보다 크다. U8은 둘을 구분해야 한다(넘길 일).
  - `total_ms ≥ latency_ms`를 검증한다. 칸이 없는 예전 JSON은 `None`으로 읽는다.
- 시도 횟수는 `Answer.attempts`에 넣는다.

**실행 무효 판단**(U6에서 확정): 실행 단위 재실행 뒤에도 남은 **서버 사정** 실패의 비율로 판단한다. 모델·문항 사정은 항목 실패로 채점하고 건수를 따로 센다. 설정 오류는 비율을 셀 것도 없이 실행을 멈춘다.

### 5) 요청 파라미터는 해시 대상만 (검토 반영)

- **호출할 때 덮어쓰기(override)를 두지 않는다.** 출력에 영향을 주는 파라미터는 모두 `settings.params`(fingerprint에 들어감)로만 받는다. 해시 밖에서 출력 조건이 바뀌는 길을 막기 위해서다.
- 예외는 하나다. `chat(messages, *, response_format=None)`의 `response_format`은 **문항 데이터(`answer_schema`)에서 나오는 값만** 넘긴다(U5 약속). 문항 데이터는 문항 세트 버전에 들어가므로 해시 밖이 아니다.
- `params`에 `model`·`messages`·`stream`·`response_format`을 쓰면 `ModelSettings` 검증에서 거부한다(`params_reserved_key`).

## 만들 것

### 1) 클라이언트 (`src/ragexp/client.py`)

```python
class ChatClient:
    def __init__(self, settings: ModelSettings, *,
                 transport: httpx.BaseTransport | None = None,     # 시험: MockTransport
                 sleep: Callable[[float], None] = time.sleep,
                 clock: Callable[[], float] = time.perf_counter,
                 now: Callable[[], float] = time.time) -> None: ...  # Retry-After 날짜 계산용
        # 자리표시 값이면 ClientConfigError. timeout·max_retries는 settings.run에서
    def chat(self, messages: Sequence[Mapping[str, str]], *,
             response_format: Mapping[str, Any] | None = None) -> Answer: ...
    def close(self) -> None: ...   # with 문 지원

def failure_class(answer: Answer) -> Literal["server", "item", "config"] | None: ...
MAX_TIMEOUT_ATTEMPTS = 2
```

**요청**:
- `POST {base_url}/chat/completions`, 본문은 `{"model", "messages", **settings.params, ["response_format"]}`
- `api_key`가 있으면 `Authorization: Bearer …` 헤더로 보낸다.
- `stream`은 쓰지 않는다.

**응답 → `Answer`**:
- `text`는 `choices[0].message.content`다(`None`이면 `""`).
- `finish_reason`: stop → stop, length → length, 그 밖·없음 → other
- `usage`: prompt_tokens → input_tokens, completion_tokens → output_tokens. 없으면 `None`
- `served_model`: 경로면 마지막 조각. 주소가 들어 있으면 기록하지 않고(`None`) 경고만 남긴다(`warnings`는 주소를 받지 않으므로).
- `attempts`, `warnings`, `usage.latency_ms`·`usage.total_ms`
- 오류면 `finish_reason="error"`, `error_kind`, `error`를 채운다.
  - `error`는 **고정 문구**다. 예: "HTTP 503", "응답 시간 초과(180초)", "연결 실패", "응답 형식 오류(choices 없음)", 설정 오류 문구(4절)

**새지 않게**:
- httpx 예외 문자열(URL이 들어 있음)은 쓰지 않는다.
- 예외를 바꿔 낼 때는 `from None`을 쓴다.
- 클라이언트는 아무것도 출력하지 않는다.
- httpx·httpcore 라이브러리 로거는 INFO에서 요청 URL을 찍는다. 지금은 레포에 로깅 설정이 없어 기본 WARNING이라 실제로 새는 길은 없다. design.md "알려진 남는 위험"에 적고, 로깅을 설정하는 U6에서 두 로거를 WARNING으로 묶는다(남은 일).

### 2) 설정 (`src/ragexp/config.py` 수정)
- `UNSET_PLACEHOLDER` 공개 상수
- `ModelSettings`:
  - `run: RunSettings` 칸(기본값)
  - `base_url` 형식 검증기(자리표시 값만 통과, 끝의 `/` 정규화)
  - `params` 예약 키 거부
  - `hide_input_in_errors=True`: 레지스트리를 거치지 않고 직접 만들다 난 검증 오류 문구에도 입력값(주소)이 나오지 않게 한다
- 로더: `config_model`에 `run` 칸이 있는 generator·judge 부품에 `run`을 주입한다.

### 3) 그 밖의 코드 (U1 타입·fingerprint)
- `types.py`:
  - `ErrorKind`에 `"client_error"`·`"config_error"`를 더한다.

  - `Usage`에 `total_ms: float | None = None`(≥0, `latency_ms` 이상)을 더한다.

- `FakeOpenAIServer`: 표준 라이브러리 `http.server` 스레드 서버다. `127.0.0.1:0`에서 뜨고, 모델 이름별로 정해 둔 답을 돌려준다. 실제 소켓 시험 2건과 U9에 쓴다.

## 설계와 다른 점

- **U1 타입**: `ErrorKind`에 `client_error`·`config_error`를, `Answer`에 `attempts`·`warnings`를, `Usage`에 `total_ms`를 더한다.
- **§7.1 실패 분류**: "서버 사정 실패(연결·시간 초과)"를 분류 셋으로 넓힌다. 서버 사정(연결·시간 초과·408·429·5xx·other)만 재실행하고 실행 무효 비율에 센다. 모델·문항 사정(client_error·parse·잘림)은 항목 실패, 설정 오류(401·403·404)는 실행을 바로 멈춘다.
- **부품 약속 추가**(§4): `run` 주입, 클라이언트는 늦게 만든다, 생성기는 클라이언트의 `Answer`를 그대로 돌려준다, 호출할 때 파라미터를 덮어쓰지 않는다(`response_format`은 문항 데이터에서만).
- 설계 §4 "모델 호출 통로"의 데이터 등급 통제(선택 기능)는 R0에서 만들지 않는다.

## 결정 (2026-11-17 승인)

1. **재시도 두 층**: 호출 안에서 서버 사정은 최대 3번, 시간 초과는 최대 2번. 실행이 끝난 뒤 서버 사정 실패 항목만 한 번 더. 429는 `Retry-After`(초·HTTP 날짜, 60초 상한)를 따른다. (승인 때 고침)
2. **실패 분류 셋**: 서버 사정·모델·문항 사정·설정 오류(4절 표). `other`는 서버 사정. (승인 때 고침)
3. **설정 오류용 `ErrorKind` 값**: `config_error`를 더한다(4절 이유).
4. **응답 모델 이름이 경로일 때 마지막 조각만 기록**(served_model·경고 모두)
5. **지연**: `latency_ms`는 마지막 시도, `total_ms`는 재시도·대기 포함, 시도 횟수는 `attempts`. (승인 때 고침)
6. **호출할 때 파라미터 덮어쓰기 없음**(`response_format`만 문항 데이터에서)
7. **`run` 주입·늦게 만들기**(클라이언트 경계)
8. **httpx 직접 의존성**(ADR 0003)
9. **크기**: M의 상한

## 승인 때 반영 (2026-11-17)

| 지적 | 반영 |
| --- | --- |
| 429 재시도와 `Retry-After`(날짜 형식·못 읽음 포함), 시간 초과는 2번 | 4절 대응표·시도 횟수·대기, 기준 3 |
| 실패 분류 셋, 설정 오류용 `ErrorKind` | 4절 분류 셋 표, `config_error`, `failure_class`, 기준 3·4 |
| `total_ms` | 4절 지연, `Usage.total_ms`, 기준 9 |
| 기준 3의 "예외 7종" | 예외 이름으로 나열 |
| 파일 표에 `tests/test_fingerprint.py` | 더함 |

승인 뒤 구현하면서 정한 세부(같은 원칙을 적용한 것):
- 1xx·3xx 같은 모르는 상태 코드는 `other`(서버 사정)로 둔다.
- `Retry-After`는 429뿐 아니라 재시도 대상 HTTP 응답(503 등)에 있으면 따른다.
- 응답 모델 이름에 주소가 있으면 `served_model`에 넣지 않고 경고만 남긴다.
- `ModelSettings`에 `hide_input_in_errors=True`를 둔다.

## 검토 반영 (design-reviewer, 2026-11-17)

지적: 높음 1·중간 4·낮음 4, 확인 필요 6. 모두 반영했다.

| 지적 | 반영 |

확인 필요 6건:
- httpx 로거는 "알려진 남는 위험"과 U6으로 넘겼다.
- 예외를 바꿔 낼 때 `from None`을 쓰고, 기준 4가 `__context__`까지 본다.
- 고정 문구만 써서 `NoUrlStr` 역효과(검증 오류 메시지에 값이 들어감)를 피한다.
- 오류일 때 `text`는 빈 문자열이다(기준 4).

- `api_key` 자리표시 값도 클라이언트가 거부한다.

### 구현 중 생긴 결정: 프록시 (2026-11-17 결정, 이번 PR에서 반영)

**문제**: httpx 기본값(`trust_env=True`)은 환경 변수 `HTTP(S)_PROXY`와 Windows 시스템 프록시를 따르지만, Windows 예외 목록(ProxyOverride)은 반영하지 않는다. 시스템 프록시가 켜진 PC에서는 사내 vLLM 호출이 Bearer 키를 실은 채 프록시를 지날 수 있다.

**결정**: 실행 설정(`run`)이 아니라 **모델별 접속 설정** `proxy: none | env`(기본 `none`)로 둔다.
- 이유: 상용 A(회사 프록시)와 로컬 B(사내망 직접)를 한 실행에서 비교한다. 실행 전체 설정 하나로는 둘 중 하나가 틀린 경로로 간다.
- `none`: `trust_env=False`. 환경 변수·시스템 프록시를 읽지 않고 직접 연결한다.
- `env`: `trust_env=True`. 환경 변수·시스템 프록시를 따른다.
- 해시에 넣지 않는다(접속 칸. `fingerprint_items()`에 없음). 값은 `none`·`env`뿐이라 `${VAR}`·SecretStr이 아닌 일반 칸이다.
- `none`에서 연결을 맺지 못하면(ConnectError·ConnectTimeout) 오류 문구에 "회사 프록시가 필요하면 이 모델 설정에 proxy: env"를 붙인다. 주소·키는 넣지 않는다.
- 실제 소켓 시험(`test_real_socket_*`)은 `proxy="none"`을 명시해서 돈다.

**시험** (실제 소켓. httpx는 transport를 따로 주면 환경 변수 프록시를 쓰지 않으므로 MockTransport로는 볼 수 없음):

| 시험 | 확인하는 것 |
| --- | --- |
| `test_proxy_none_ignores_env_proxy` | `HTTP_PROXY`가 가짜 프록시를 가리켜도 기본값(`none`)은 대상 서버로 직접 간다. 프록시는 요청을 하나도 받지 않는다 |
| `test_proxy_env_follows_env_proxy` | `env`면 요청이 가짜 프록시로 간다(절대 주소 꼴 경로). 대상 서버는 요청을 받지 않는다 |
| `test_proxy_hint_on_connect_failure` 2건 | `none`의 ConnectError·ConnectTimeout에 안내가 붙고 값은 새지 않는다. `env`에는 붙지 않는다 |
| `test_proxy_hint_not_on_other_failures` | ReadError·ReadTimeout·503에는 안내가 붙지 않는다 |
| `test_proxy_default_is_none`, `test_proxy_setting_is_per_model_and_not_hashed`, `test_proxy_unknown_value_rejected` | 기본값 `none`, arm마다 다르게 쓸 수 있음, fingerprint 그대로, 모르는 값 거부 |
