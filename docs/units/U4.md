# U4 법령 수집·스냅샷

상태: 구현 완료 (2026-11-18), 커밋·PR 대기
관련: docs/design.md §4, §5, §6.1, §6.3, §8.1 · docs/units/R0.md · docs/STATUS.md "남은 일 모음" · 브랜치 `u4-law-corpus`

## 나눔 (크기 M 이내로)

R0.md의 U4(법령 말뭉치·조 단위 청킹)는 검토에서 L(약 2일)로 판단됐다. 그래서 둘로 나눈다(2026-11-18 승인, 결정 0).

| 단위 | 만들 것 | 크기 |
| --- | --- | --- |
| **U4 법령 수집·스냅샷** (이 메모) | `ragexp corpus fetch-law`, 스냅샷 폴더·manifest·내용 해시·검증, OC 누출 막기, 실제 응답으로 구조 확인 | M |
| **U4b 조 단위 파싱·청킹** (다음 메모) | XML 파서, `law_api` Corpus, `law_article` Chunker, entry point, 구성 로더의 경로 칸 | S~M |

- 수집을 먼저 하는 이유: U4 끝에 실제 응답을 받아 XML 구조를 확인한 뒤 파서를 만들 수 있다. 추측한 구조로 파서를 먼저 만들면 되돌아갈 일이 생긴다. 사용자가 예제 문항을 쓸 본문도 U4 끝에 나온다.
- U5는 U4b 뒤에 시작한다.
- 덩어리 ID와 조문 처리 규칙(요청 항목 3·4)은 **이 메모 6·7절에서 확정**한다. U4b 메모는 구조 확인 결과와 구현 세부만 더한다.

## 목표

- `ragexp corpus fetch-law`가 법령 이름과 기준일로 그날 시행 중인 본문(eflaw)을 받아 스냅샷 폴더(원문 XML + `manifest.json` + 출처표시)를 만든다.
- 스냅샷의 내용 해시는 결정적이고, 읽을 때 파일 해시를 다시 검증한다.
- 인증키(OC)는 스냅샷·manifest·오류(예외 연쇄 포함)·로그·CLI 출력·레포의 시험 자료 어디에도 남지 않는다.

## 넘어온 항목 (STATUS.md "남은 일 모음")

| 항목 | 처리 |
| --- | --- |
| 법령 수집 주소는 코드에 고정, OC는 `LAW_API_OC` (U2) | **U4에서 확정.** 주소는 `ragexp.datasets.law_api`의 상수(`https://www.law.go.kr/DRF/`)다. 구성 YAML에는 주소도 OC도 없다. OC는 수집할 때만 쓰고, U4b Corpus는 OC 칸이 없다. |
| entry point 시험 격리 (U1) | **U4b로 넘긴다.** 내장 부품을 처음 entry point로 선언하는 단위가 U4b다. |

## 1. 국가법령정보센터 Open API 이용 조건 (재배포)

2026-11-18에 법제처 페이지를 읽고 확인한 것이다. 법적 판단이 아니라 페이지 내용을 정리한 것이다.

| 출처 | 확인한 내용 |
| --- | --- |
| open.law.go.kr 이용안내(`/LSO/information/guide.do`) "저작권 정책" | "제공된 법령정보는 영리 목적의 이용을 포함하여 자유로운 활용이 보장됩니다." 저작권은 "「저작권법」의 보호를 받는 범위 내에서 법제처에 있습니다." 출처를 표기하지 않거나 다른 기관으로 명기하면 형사처벌 대상(저작권법 제137·138조)이라고 적혀 있다. |
| law.go.kr "법적효력/저작권"(`/LSW/legalCopyright.do`) | 저작권법 제7조(보호받지 못하는 저작물)를 들고, 법제처가 저작재산권을 모두 가진 저작물은 "별도의 이용허락 없이 자유이용이 가능"하다고 한다. 법령정보는 법적 효력이 없는 참고자료라고 안내한다. |
| open.law.go.kr 서비스 소개·회원가입 주의사항 | 가공해서 자기 서비스를 만들 수 있다. 모든 DATA 활용은 공동활용 승인 뒤에 가능하다. 짧은 시간의 과도한 호출은 이용 제한 사유다. |
| 공공데이터포털(data.go.kr 15000115) | 이용허락범위: 공공누리 **제1유형(출처표시)**, 단서 "제3자 권리 포함: 저작권 표시". |

**정리**:
- 재배포나 2차 가공을 **금지하는 문장은 없다**. 조건은 **출처표시**다.
- 법령 본문 자체는 저작권법 제7조에 따라 보호받지 않는 저작물이다.
- 다만 "재배포해도 된다"고 **명시한 문장도 없다**. 정해진 출처표시 문구도 없다.
- "제3자 권리 포함" 단서는 별표·서식처럼 다른 저작물이 섞일 수 있는 부분을 가리키는 것으로 보인다(추측).

**그래서 안전한 쪽으로 간다**(요청의 "확인 못 하면" 규칙을 따름):
- 레포에는 받아 오는 스크립트와 **작은 시험 고정 자료**만 넣는다.
  - 고정 자료는 **합성 자료**다. 손으로 쓴 가짜 법령을 실제 응답 구조에 맞춰 만든다.
  - 실제 응답 발췌는 넣지 않는다(4절 OC 이유도 있음).
- 받은 전체 스냅샷은 `workspace/snapshots/`에 둔다(git 무시).
- 전체 스냅샷을 `examples/law_ko/`에 넣을지는 U9 전에 정한다(결정 필요 1).
- 스냅샷 폴더에는 출처표시 파일 `SOURCE.md`를 둔다. 같은 문구를 manifest의 `source` 칸에도 넣는다.
  - 문구: "출처: 국가법령정보센터(법제처), https://www.law.go.kr — 공공누리 제1유형. 법적 효력이 없는 참고자료입니다."
- 별표 파일(HWP·PDF 링크)은 따라가 받지 않는다.

## 2. 대상 법령·기준일·eflaw 호출 인자

**대상 법령 4개**(R0.md 그대로). 이름은 법령명 원문과 **정확히** 같아야 한다.

| 법령명 | 종류 |
| --- | --- |
| 보조금 관리에 관한 법률 | 법률 |
| 보조금 관리에 관한 법률 시행령 | 대통령령 |
| 국가재정법 | 법률 |
| 개인정보 보호법 | 법률 |

법령ID·MST·시행일자는 수집할 때 알아내 manifest에 남긴다. 지금은 확인할 수단이 없어 메모에 적지 않는다.

**기준일**:
- 스냅샷 하나는 기준일 하나를 갖는다. 기준일은 **"그날 시행 중인 판"**을 뜻한다.
- 판 목록에서 `시행일자 ≤ 기준일`인 판 중 가장 늦은 판을 고른다.
- 시행일자가 같은 판이 여럿이면(같은 날 시행되는 개정이 겹침) 공포일자 → 공포번호 → MST가 가장 큰 판을 고른다. 늦게 공포된 판이 앞 개정을 포함하기 때문이다. 판 목록의 순서와 상관없이 같은 판을 고른다.
- 기준일은 **2026-10-29**다(2026-11-18 결정). DASP P0 스냅샷과 같은 날이라, R2에서 P0를 재현해 검증할 때 조문 본문이 같다. U4 끝에 고른 판(MST·시행일자)을 P0 스냅샷과 대조할 수 있으면 대조해 결과에 적는다.

**호출 순서와 인자** (근거: 공식 가이드 `lsEfYdInfoGuide`·`lsEfYdListGuide`, 서드파티 실측 기록):

| 단계 | 호출 | 인자 | 쓰는 응답 칸 |
| --- | --- | --- | --- |
| ① 법령ID 찾기 | `lawSearch.do` | `target=eflaw`, `type=XML`, `query=<법령명>`, `display=100` | `법령명한글`이 이름과 **정확히 같은** 행의 `법령ID`. 서로 다른 법령ID가 0개거나 2개 이상이면 후보 이름을 보여 주고 멈춘다. |
| ② 판 목록 | `lawSearch.do` | `target=eflaw`, `type=XML`, `LID=<법령ID>`, `nw=1,2,3`(연혁·시행예정·현행 모두), `display=100`, `page=…` | 행마다 `법령일련번호`(=MST)·`시행일자`·`공포일자`·`공포번호`. `totalCnt`를 보고 모든 쪽을 읽는다. 기준일 이전 판이 없으면 멈춘다. |
| ③ 본문 | `lawService.do` | `target=eflaw`, `type=XML`, `MST=<법령일련번호>`, `efYd=<그 판의 시행일자>` | 본문 XML 바이트 전체를 그대로 저장한다. |

- 모든 요청에 `OC=<LAW_API_OC>`가 붙는다.
- **`ID`+`efYd` 조합은 쓰지 않는다.** 실측 기록에 따르면 어떤 날짜를 넣어도 빈 결과가 온다. `MST`만 주는 조합도 HTML 오류 페이지가 와서 쓰지 않는다.
- `efYd`는 기준일이 아니라 **고른 판의 시행일자**다. 짝이 맞지 않으면 HTML 오류 페이지가 온다.
- `JO`(조 지정)는 쓰지 않는다. `chrClsCd`는 기본값(한글)이다.
- 응답 검사:
  - XML로 읽을 수 없거나 `<!DOCTYPE`이 있는 응답(HTML 오류 페이지 등)은 받지 않는다. 고정 문구로 멈추고 "인증키 승인과 신청한 법령 종류, MST·시행일 짝을 확인하세요"를 붙인다. 서드파티 기록에 따르면 구독 문제가 아닐 때도 같은 페이지가 온다.
  - 본문의 `법령ID`가 ①에서 찾은 값과 다르면 멈춘다(manifest·파일 이름과 내용이 어긋나지 않게).
- ①·②의 검색 응답은 **저장하지 않는다**. 검색 응답의 `법령상세링크`에 요청한 OC가 들어 있을 수 있다(구조 확인 때 본다).

**수집 통로**: U3 `ChatClient`는 chat 전용이라 쓰지 않는다. httpx를 직접 쓰고 U3의 원칙만 따른다.
- https만 쓴다. 리다이렉트를 따라가지 않는다(OC가 다른 곳으로 가지 않게).
- 시간 제한은 30초다.
- 다시 시도하는 것은 연결 오류·시간 초과·429·5xx뿐이다. 전체 3번, 대기 1초·2초다. 그 밖의 4xx는 1번에 멈춘다. 대기 함수를 주입할 수 있어 시험은 기다리지 않는다.
- U3과 달리 `Retry-After`를 따르지 않고 시간 초과 상한(2번)도 두지 않는다. 호출이 10번 안팎이고 사람이 지켜보며 한 번 돌리는 명령이라 단순하게 둔다.
- 호출과 호출 사이에 0.5초를 쉰다(과도한 호출 제한 대비).
- 프록시는 기본 **`none`**이다(2026-11-18 결정). 모델 호출(U3)과 같은 규칙이다. OC가 요청 주소에 들어가므로 환경 변수·시스템 프록시를 몰래 따르지 않는다.
  - 회사 프록시가 필요하면 `--proxy env`로 켠다.
  - `none`에서 연결을 맺지 못하면 오류 문구에 "회사 프록시가 필요하면 --proxy env"를 붙인다(U3과 같은 안내).

## 3. 스냅샷 위치와 manifest

**위치**:

| 무엇 | 어디 | 레포에 |
| --- | --- | --- |
| 받은 스냅샷 | `workspace/snapshots/<이름>/` (기본 이름 `law-ko-<기준일 YYYYMMDD>`, 이번에는 `law-ko-20261029`) | 넣지 않음(`workspace/`는 이미 git 무시) |
| 시험 고정 자료 | `tests/fixtures/law/` (합성) | 넣음 |
| 예제 스냅샷 | `examples/law_ko/snapshot/` | **U9 전 결정**(결정 필요 1) |

- 설계 §5 예시의 `data/snapshots/…`는 §8.1의 `workspace/snapshots/…`로 맞춘다(설계와 다른 점).
- 스냅샷은 한 번 만들면 바꾸지 않는다.
  - 출력 폴더가 이미 있으면 멈춘다.
  - 받는 동안에는 같은 위치의 임시 폴더(`.<이름>.partial`)에 쓰고, 모두 성공하면 이름을 바꾼다. 실패하면 임시 폴더를 지운다.
  - 프로세스가 강제로 끝나 임시 폴더가 남아 있으면, 다음 실행은 지우지 않고 "남은 임시 폴더를 지우고 다시 돌리세요"로 멈춘다.

**폴더 모양**:

```text
law-ko-20261029/
├─ manifest.json
├─ SOURCE.md                 # 출처표시
└─ laws/
   ├─ <법령ID>.xml           # 본문 응답 바이트 그대로
   └─ …
```

**manifest.json**:

```json
{
  "schema": "ragexp.law_snapshot/1",
  "source": "출처: 국가법령정보센터(법제처) … 공공누리 제1유형 …",
  "api": {"service": "lawService.do", "target": "eflaw", "type": "XML"},
  "as_of": "2026-10-29",
  "fetched_at": "2026-11-18T05:12:00Z",
  "ragexp_version": "0.x.y",
  "laws": [
    {"name": "국가재정법", "law_id": "000000", "mst": "000000", "kind": "법률",
     "effective_date": "2026-01-01", "promulgation_date": "2025-12-01", "promulgation_no": "00000",
     "file": "laws/000000.xml", "sha256": "…", "bytes": 123456}
  ],
  "content_hash": "snap-…"
}
```

- **받은 날짜**는 `fetched_at`(UTC), **기준일**은 `as_of`, **파일별 해시**는 `laws[].sha256`이다.
- 요청 주소와 OC는 남기지 않는다. 남기는 호출 인자는 `target`·`type`, 그리고 법령마다 `mst`·`effective_date`(=`efYd`)뿐이다.
- **내용 해시** `content_hash`:
  - `(file, sha256)` 쌍을 `file` 순으로 정렬해 U2의 정규 JSON으로 만들고, 그 sha256을 낸다.
  - `fetched_at`·`as_of`·`source`·`ragexp_version`은 넣지 않는다. 그래서 같은 본문을 다른 날 받아도 해시가 같다.
- **`load_snapshot(path)`**(U4b Corpus가 쓴다):
  - manifest의 `schema`를 확인한다.
  - `file`은 `laws/<6자리 숫자>.xml` 꼴만 받는다(`../` 등은 거부). `law_id`와 파일 이름이 맞는지 본다.
  - 파일마다 sha256을 다시 계산해 대조한다.
  - `content_hash`를 다시 계산해 대조한다.
  - 다르면 파일 이름만 담은 오류로 멈춘다. 돌려주는 해시는 **다시 계산한 값**이다.

## 4. OC가 새지 않게

| 새는 길 | 막는 방법 | 시험 |
| --- | --- | --- |
| 스냅샷 파일 | 검색 응답은 저장하지 않는다. 본문 응답 바이트에 OC 문자열이 있으면 **저장을 거부**하고 멈춘다. 지우지 않는다(U2의 "마스킹하지 않음" 원칙). manifest에 요청 주소를 쓰지 않는다 | 스냅샷 폴더의 모든 파일 바이트에 OC가 없음. OC가 든 응답은 거부 |
| 레포의 시험 자료 | 고정 자료는 합성이다. `법령상세링크`처럼 OC 자리가 있는 곳은 시험용 가짜 값(`oc-test-SECRET-7f3a`)만 쓴다 | `tests/fixtures/law/` 아래 모든 파일에서 `OC=` 뒤의 값이 시험용 가짜 값뿐임 (이 폴더만 보는 시험이다. 첫 번째 겹의 패턴을 늘리지 않는다) |
| 오류 문구·예외 | 고정 문구만 쓴다(법령명·단계·오류 종류·상태 코드). 주소·응답 본문을 넣지 않는다. U3 클라이언트처럼 `except` 안에서는 실패 값만 만들고, 예외는 **`except` 밖에서** 낸다. 그래서 `__context__`에 httpx 예외(요청 URL 포함)가 남지 않는다 | 실패 종류마다(연결·시간 초과·4xx·5xx·HTML 응답·XML 오류·법령ID 불일치·이름 0개/여러 개) `str`·`repr`·`traceback.format_exception`, 그리고 `__cause__`·`__context__` 연쇄 전체에 OC·주소가 없음 |
| 로그 | httpx는 INFO에서 요청 주소(OC 포함)를 찍는다. 수집하는 동안 `httpx`·`httpcore` 로거 수준을 WARNING 이상으로 올리고 끝나면 되돌린다. 우리 코드는 주소를 로그에 쓰지 않는다 | 루트와 httpx 로거를 DEBUG로 둔 채 수집(성공·실패)해도 `caplog` 기록에 OC가 없음 |
| CLI 출력 | 오류는 위 고정 문구로만 낸다. `--oc` 옵션은 없다 | `CliRunner`로 성공·실패를 돌려 stdout·stderr에 OC가 없음 |
| 함수 인자 | `fetch_law_snapshot`은 `oc: SecretStr`로 받고, 요청을 만드는 곳에서만 값을 꺼낸다 | `repr` 시험에 포함 |
| OC 없음 | `LAW_API_OC`가 없거나 비면 호출 전에 "LAW_API_OC 환경 변수를 넣으세요"로 멈춘다 | 위 문구, 호출 0번 |

- OC가 아주 짧거나 흔한 문자열이면 "응답에 OC가 들어 있음"이 잘못 걸릴 수 있다. 그때는 오류 문구가 그 가능성을 알려 준다. 지금은 규칙을 더 늘리지 않는다.
- **사람이 OC를 넣는 법**(결정 필요 4와 README에 적음):
  - Claude Code를 띄우기 **전에** OS·셸 환경 변수로 넣는다.
  - `!` 명령 줄에 값을 쓰지 않는다. 대화 기록에 남는다.
  - ragexp는 `.env`를 자동으로 읽지 않는다.

## 5. 구조 확인 (U4의 마지막 일)

공식 가이드에는 아래가 나와 있지 않다. 그래서 U4 끝에 실제 응답을 한 번 받아 확인하고, 결과를 U4b 메모의 재료로 이 메모 "결과"에 적는다(응답 원문은 레포에 넣지 않음).

- XML 태그 계층: `기본정보`·`조문`·`조문단위`처럼 감싸는 태그와, 검색 응답의 행 태그
- `조문여부` 값 목록(조문·전문)
- 삭제 조문 표시 형식
- 편·장·절이 겹칠 때 전문 줄의 모양
- 법령ID의 자릿수(0 채움 여부)
- 검색 응답의 `법령상세링크`에 OC가 들어 있는지

가짜 API와 합성 자료는 공식 가이드의 칸 이름으로 먼저 만든다. 실제 구조가 다르면 고치고, 그것을 "결과"에 적는다.

## 6. 덩어리 ID와 법령ID (U4b가 구현, 여기서 확정)

**형식**: `law:<법령ID>:제N조` 또는 `law:<법령ID>:제N조의M` (설계 §6.3의 `law:000729:제27조`와 같은 꼴).

| | 법령ID (`ID`·`LID`) | 법령일련번호 (`MST`) |
| --- | --- | --- |
| 가리키는 것 | 법령 하나(판이 바뀌어도 같음) | 법령의 **판** 하나(개정될 때마다 새 번호) |
| 덩어리 ID에 | **쓴다** | 쓰지 않는다. manifest에만 남긴다 |

- 법령ID를 쓰는 이유: 개정으로 MST가 바뀌어도 바뀌지 않은 조문의 ID는 그대로다. 그래서 문항의 `gold`를 새 스냅샷에서도 쓸 수 있다.
- 내용이 바뀌었는지는 ID가 아니라 스냅샷 내용 해시(구성 버전)로 구분한다. 스냅샷에 없는 gold는 U5 로더가 오류로 막는다.
- 법령ID는 **문자열**로 다루고, 0으로 채운 6자리(`000729`)로 정규화한다. 6자리 숫자로 만들 수 없으면 오류다.
- 시행령은 법률과 다른 법령ID를 갖는다. 그래서 번호가 같은 "제5조"라도 ID가 다르다.
- `Document.doc_id`는 `law:<법령ID>`, `Section.section_id`는 `제N조[의M]`, `Chunk.chunk_id`는 `<doc_id>:<section_id>`다.
- 중복 검사는 나눠 맡는다. Chunker는 문서 안에서 덩어리 ID가 겹치는지 보고, Corpus는 `doc_id`(법령ID)가 겹치는지 본다. 덩어리 ID 앞에 `doc_id`가 붙으므로 둘을 합치면 말뭉치 전체에서 겹치지 않는다.

## 7. 조문 처리와 덩어리 본문 (U4b가 구현, 여기서 확정)

| 대상 | 처리 |
| --- | --- |
| 일반 조문(`조문여부`=조문) | 덩어리 하나 |
| 가지조문(`조문가지번호` 있음) | `제N조의M`이다. 가지번호가 없거나 0이면 `제N조`다 |
| 편·장·절 제목 줄(`조문여부`=전문) | 덩어리를 만들지 않는다. 뒤 조문들의 `meta.chapter`가 된다. 겹치면 "제2장 … > 제1절 …"처럼 잇는다(구조 확인 뒤 U4b에서 세부 확정) |
| 삭제 조문(본문이 "제N조 삭제 <날짜>" 꼴) | **덩어리로 넣는다**(2026-11-18 결정). ID는 다른 조문과 같은 꼴(`제N조[의M]`)이고 `meta.deleted=true`다. 본문은 "제N조 삭제 <날짜>" 원문 그대로다. 이유: 삭제된 조문을 묻는 질문에 "삭제됐다"고 답할 근거가 되고, P0 재현 때 조문 수가 맞는다. 삭제 판정 규칙(본문 꼴, `조문제개정유형` 등)은 구조 확인 뒤 U4b에서 정한다 |
| 부칙 | 덩어리로 만들지 않는다. 부칙마다 "제1조(시행일)"이 되풀이돼 ID 체계가 달라야 하기 때문이다. 원문 XML에는 남는다 |
| 별표 | 덩어리로 만들지 않는다(1절의 제3자 권리 단서, 본문이 HWP·PDF 파일인 경우가 많음) |

**덩어리 본문**:
- `Chunk.heading`은 `<법령명> 제N조의M(조문제목)`이다. 제목이 없으면(삭제 조문 포함) 괄호를 뺀다. 법령명을 넣는 이유는 근거 안에서 법률과 시행령의 같은 번호 조를 구분하기 위해서다.
- `Chunk.text`는 아래 줄들을 `\n`으로 잇는다. 원문 문자는 바꾸지 않는다(개정 표시 `<개정 2020.1.1>`도 그대로 둔다).
  1. `조문내용`: "제27조(보조금의 반환) …" 같은 본문이다. 항이 있으면 "제3조(정의)"만 들어 있다.
  2. 항마다 `항내용` (예: "① …")
  3. 그 항의 호마다 `호내용` (예: "1. …")
  4. 그 호의 목마다 `목내용` (예: "가. …")
- 정리는 공백만 한다.
  - 칸마다 앞뒤 공백을 떼고, 칸 안의 줄도 줄마다 앞뒤 공백을 뗀다.
  - 빈 줄은 뺀다. 들여쓰기는 넣지 않는다.
- 삭제 조문의 `Chunk.text`는 `조문내용` 한 줄("제N조 삭제 <날짜>") 그대로다.
- `Chunk.meta`: `law_id`, `law_name`, `article_no`(int), `branch_no`(int, 없으면 0), `chapter`(없으면 빈 문자열), `effective_date`(판의 시행일자, `YYYY-MM-DD`), `deleted`(bool, 삭제 조문이면 true).
- `Document.meta`에는 출처 정보만 둔다(U1 타입 설명 그대로). 법령ID·MST·법령명·종류·시행일자·공포일자·공포번호다. 부칙 개수 같은 구조 요약은 넣지 않는다.
- 6·7절 규칙은 **확정**이다(2026-11-18 승인). U4b 메모는 구조 확인으로 정해지는 세부(태그 이름, 삭제 판정 규칙, 장절이 겹칠 때 잇는 모양)만 더하고, 이 규칙을 바꾸려면 다시 승인을 받는다.

**U4b에 함께 넘기는 구현 약속**(검토 반영):
- **경로 칸**: 구성 로더가 `corpus.snapshot`이라는 이름을 직접 알지 않게 한다.
  - `ragexp.config`에 경로 표시 타입(예: `RelativeDir`)을 둔다.
  - 로더는 모든 부품의 `config_model`에서 이 타입의 칸을 찾아 YAML 기준 상대 경로로 푼다. `SecretStr` 표시를 읽는 기존 방식과 같다.
  - 절대 경로는 거부한다. 기존 `_relative_file`과 같은 검사를 쓴다.
  - 이 약속은 design.md §4 "부품이 지킬 약속"에 더한다.
- **해시 검증 시점**: Corpus는 생성자(`registry.create` 때)에서 `load_snapshot`으로 검증한다. `fingerprint()`는 다시 계산한 해시만 쓴다. 그래서 파일이 바뀐 스냅샷은 `config check` 단계에서 멈춘다.
- **XML 안전**: 파서도 `<!DOCTYPE`이 있는 문서를 거부한다(표준 라이브러리 ElementTree 사용, 새 의존성 없음).
- **내장 부품 등록**: `pyproject.toml` entry point로만 노출한다. `components/__init__.py`에서 불러오지 않는다(순환 import, 쓸 때만 불러온다는 원칙). pyproject를 고친 뒤에는 `uv sync`를 다시 해야 한다.
- **시험용 레지스트리**: 구성 버전 시험은 entry point를 읽지 않는 시험용 레지스트리에 부품을 `add`해서 쓴다. 내장 부품 등록 시험은 `Registry()`로 한다.

## 만들 것 (U4)

1. `ragexp.datasets.law_api`
   - `fetch_law_snapshot(names, as_of, out_dir, *, oc: SecretStr, transport=None, sleep=time.sleep, proxy="env") -> Manifest`: 2절 순서로 받아 3절 폴더를 만든다.

3. 가짜 법령 API `tests/fakes/fake_law_api.py`: httpx `MockTransport`로 검색·판 목록(여러 쪽)·본문·HTML 오류·5xx·429·시간 초과를 흉내 낸다.
4. 합성 고정 자료 `tests/fixtures/law/`: 검색 응답, 판 목록(여러 쪽), 본문 XML(가짜 법령 "시험법"), `SOURCE.md`.
5. 구조 확인(5절): 실제 응답 4개를 받아 결과를 이 메모에 적는다.

1. 기준일에 시행 중인 판을 고르고, `MST`+`efYd`로 부른다(`ID`+`efYd`는 쓰지 않음). 시행일자가 같은 판이 여럿이면 정한 순서로 고른다. 판 목록 여러 쪽을 읽는다. 이름이 0개·여러 개면 멈춘다. (`test_law_fetch.py`)

4. 파일을 고쳤거나 `file` 경로가 이상한 스냅샷은 `load_snapshot`이 오류로 멈춘다. (`test_law_snapshot.py::test_tampered_rejected`, `test_bad_file_path_rejected`)
5. OC가 스냅샷 파일·manifest·오류(예외 연쇄 포함)·로그(httpx DEBUG 포함)·CLI 출력에 남지 않는다. OC가 든 응답은 저장하지 않는다. 레포의 고정 자료에는 시험용 가짜 OC만 있다. (`test_law_secrets.py`)
6. 실제 API로 법령 1개를 받는 시험이 있다. `@pytest.mark.network`이고, `LAW_API_OC`가 없으면 건너뛴다. 기본 시험은 네트워크 없이 돈다.
7. 구조 확인 결과(5절 항목)가 이 메모 "결과"에 있다. 실제 4개 법령 스냅샷이 `workspace/snapshots/law-ko-<기준일>/`에 있다(사람이 받음, 레포 밖).
8. `/unit-check`(ruff·format·mypy strict·pytest·pre-commit) 통과.
9. CI: PR #n.

| 검색 응답 행 | 검색 응답은 저장하지 않아 직접 보지 않았다. 4개 법령 모두 `law` 행, `totalCnt`, `법령명한글`·`법령ID`·`법령일련번호`·`시행일자`·`공포일자`·`공포번호`·`법령구분명`으로 정확히 찾고 판을 골랐다. 그래서 이 칸 이름들은 맞다. `LID`+`nw=1,2,3` 판 목록도 동작했다 |
| `조문여부` 값 | `조문`, `전문` 둘뿐이다. 시행령에는 `전문`이 없다(장 구분이 없음) |
| 삭제 조문 | `조문내용`이 `제N조[의M] 삭제 <YYYY.M.D>` 한 줄이고, `조문제목`은 비어 있으며 `항`이 없다. **`조문제개정유형`은 모든 조문단위가 판 단위 값(`일부개정`)이라 삭제 판정에 쓸 수 없다.** 판정은 `조문내용`의 꼴(`^제\d+조(의\d+)?\s+삭제\s*<[^>]+>$`)로 한다. 이 꼴로 찾으면 8개(1·2·3·2)이고, 제목에 "삭제"가 든 조문(`제36조(개인정보의 정정ㆍ삭제)`)은 걸리지 않는다 |
| 편·장·절 전문 줄 | `조문내용`은 앞 공백(길이가 제각각) + `제N장 제목`이고, 뒤에 `<개정 …>`·`<신설 …>`이 붙을 수 있다. 장 바로 뒤에 절이 오면 **조문키가 같은 `전문` 단위 두 개**가 이어진다(예: `0016000` 제2장 예산 → 제1절 총칙). 그 뒤의 절 줄만 따로 오면 장은 그대로다. `제4장의2`(조문키 `0085020`), 삭제된 장(`제6장 삭제 <2023.3.14>`)도 있다. 그래서 U4b는 장과 절을 수준별로 들고 있다가 장이 바뀌면 절을 비워야 한다 |
| 조문키 | 7자리 = 조문번호 4 + 가지번호 2 + 구분 1(전문 0, 조문 1). 예: `0001001` 제1조, `0085020` 제4장의2(제85조의2 앞) |
| 법령ID 자릿수 | 본문에서는 0으로 채운 6자리다(`000729`, `003650`). 덩어리 ID 규칙(6절)과 맞다 |
| 검색 응답의 OC | **들어 있다.** CLI 참고 줄이 "예"였다. 검색 응답을 저장하지 않기로 한 것이 맞았다. 본문 4개에는 OC가 없어 저장 거부가 걸리지 않았다 |

**7절 규칙과 다른 실제 모양** (규칙은 그대로 두고 U4b 구현에서 처리한다):
- 7절은 "항이 있으면 `조문내용`에 `제3조(정의)`만 들어 있다"고 적었다. 하지만 ①이 없는 조문(`제2조(정의) 이 법에서 … 다음과 같다.`)은 **`조문내용`에 머리말 전체가 있고, `항`에 `항내용` 없이 `호`만 있다.** 7절의 이어 붙이기 규칙(빈 칸은 뺌)으로 그대로 처리된다.
- `항내용`이 `①국가의 …`처럼 번호 뒤에 공백이 없을 때가 있다. 원문 그대로 둔다(7절).
- `목내용`처럼 끝에 줄바꿈이 붙은 칸이 있고, 칸 안에 줄이 여럿인 경우가 법령마다 3~4개 있다. 7절의 줄마다 공백 떼기 규칙으로 처리된다.

### U4b로 넘기는 것 (2026-11-18 결정)

1. **기준일에 아직 시행되지 않은 문장**(확정): 해당 조문의 `meta`에 `기본정보/조문시행일자문자열` 원문을 남긴다(칸 이름은 U4b 메모에서 정함).
   - 근거: 개인정보 보호법의 `조문시행일자문자열`이 `20270701:제32조의2제1항 단서,제75조제2항제15호`다. 2026-09-11 판 본문에 2027-07-01부터 시행되는 문장이 들어 있다. 조문마다 있는 `조문시행일자`로는 드러나지 않는다.
   - 국가재정법의 `별표시행일자문자열`(`20270101:별표1`)은 별표를 덩어리로 만들지 않으므로 영향이 없다.
   - 예제 문항은 제32조의2와 제75조를 피한다(사람이 반영).
2. **`조문참고자료`**(확정): 덩어리 본문에 넣지 않는다. P0와 같다.
3. **장·절 잇기**(확정): 장과 절을 수준별로 들고 있다가, 장이 바뀌면 절을 비운다. `meta.chapter`는 "제2장 … > 제1절 …" 꼴이다. 7절의 "구조 확인 뒤 U4b에서 세부 확정"을 이것으로 정한다.
4. **U4b 완료 기준에 더한다**: P0와 조문 수·삭제 수·가지조문 수가 일치한다(354·8·114, 법령별 위 표).
5. `조문변경여부`·`조문이동이전`·`조문이동이후`는 판 사이 변경 정보로 보인다. R0 청킹에는 쓰지 않는다.
6. **스냅샷을 읽는 쪽의 약속**(구현 검토의 "확인 필요"에서):
   - 덩어리에 들어가는 값(법령명·시행일자 등)은 **XML `기본정보`에서 읽는다.** 아니면 manifest 값과 XML을 대조한다. manifest의 `name`·`mst`·`effective_date`·`kind`는 내용 해시 밖이라, manifest만 고쳐도 해시가 그대로이기 때문이다.
   - 덩어리 순서는 법령ID 순으로 정렬한다. `manifest.laws`의 순서는 해시 밖이다.
   - Corpus는 manifest에 있는 파일만 읽는다(`laws/`의 다른 파일은 무시).
   - Corpus fingerprint에는 `content_hash`만 넣는다. `source` 문구에는 주소(`https://www.law.go.kr`)가 있어 `check_fingerprint`에 걸린다.

### 구현이 메모와 다른 점

설계를 어기는 것은 없다. 대부분 메모보다 엄격하게 하거나 범위를 넓힌 것이다.

- `fetch_law_snapshot`은 `Manifest`가 아니라 `FetchResult`(경로·manifest·검색 응답에 OC가 되돌아왔는지)를 돌려준다. 구조 확인 항목 "법령상세링크에 OC가 있나"를 검색 응답을 저장하지 않고 알기 위해서다. 그래서 CLI에 "참고: 검색 응답에 인증키가 들어 있었나" 줄이 더 있다.
- 함수의 `proxy` 기본값은 `"none"`이다(결정 5를 따름. 만들 것 1의 서명에는 `"env"`로 남아 있었음). 시험용 `now` 인자가 더 있다.
- `SOURCE.md`는 고정 자료로 두지 않았다. 수집할 때 만들고 시험이 내용을 확인한다.
- ① 법령명 검색도 모든 쪽을 읽는다(`page`를 보냄). 쪽 수 상한은 50이다.
- 다시 시도하는 범위가 조금 넓다. `RemoteProtocolError`와 `NetworkError` 전체(읽기·쓰기 오류 포함)도 다시 시도한다.
- 응답 거부 조건이 더 있다. `<!ENTITY`가 있는 응답과 루트가 `html`인 응답도 받지 않는다.
- 호출 전에 법령명을 검사한다(비었거나, 앞뒤 공백이 있거나, 같은 이름이 두 번). 서로 다른 이름이 같은 법령ID를 가리켜도 멈춘다.
- `load_snapshot`은 `bytes`가 맞는지와 같은 `file`이 두 번 나오는지도 본다. 법령ID·MST·날짜 숫자는 ASCII 숫자만 받는다(전각 숫자 거부).
- README에 사용법과 OC 넣는 법을 적었다. PowerShell `Read-Host -AsSecureString`을 그대로 넣으면 값이 `System.Security.SecureString`이 되는 함정도 함께 적었다.

### 구현 검토 반영 (design-reviewer, 2026-11-18)

지적은 중간 1건, 낮음 4건이다. OC가 새는 길은 찾지 못했다.

| 지적 | 반영 |
| --- | --- |
| [중간] 4절에서 약속한 README의 "OC 넣는 법"이 없음 | README에 `corpus fetch-law` 절을 더했다(사용법, 띄우기 전에 환경 변수로 넣기, `!` 줄에 값을 쓰지 않기, `.env`를 읽지 않음). 영어 요약에도 한 줄 더했다. 파일 표에 README를 넣었다 |
| [낮음] `test_proxy_default_none`의 수집 부분이 아무것도 증명하지 못함(httpx는 transport를 주면 환경 변수 프록시를 쓰지 않음) | 그 부분을 지웠다. 대신 환경 변수 프록시를 넣은 채 transport 없이 클라이언트를 만들어, `none`이면 프록시 transport가 없고 `env`면 생기는지(`_mounts`) 확인한다 |
| [낮음] `\d`가 유니코드 숫자도 받음 | 정규식과 pydantic pattern을 `[0-9]`로 바꾸고, 수집 쪽 숫자 검사도 ASCII 숫자만 받게 했다. 전각 숫자 시험 3건(경로·법령ID·MST)과 `normalize_law_id` 시험 4건을 더했다 |
| [낮음] STATUS.md가 지금 상태와 다름 | `/unit-report`가 갱신할 때 반영한다(결정 4 확정, 약관 확인 끝남 → 결정 1로 바꿈, entry point 격리는 U4b로) |
| [낮음] 완료 기준 3의 "한 바이트"와 시험이 다름 | `test_content_hash_changes_with_one_byte`가 정확히 한 바이트(공포번호 숫자 하나)만 바꾼 본문으로 시험하게 했다 |

"확인 필요" 중 U4b 몫 4건은 위 "U4b로 넘기는 것" 6번에 적었다. 그 밖의 것은 이렇게 처리했다.
- OC 검사가 원문과 퍼센트 인코딩 대문자 꼴만 본다는 점: 실제 사례가 없는 가설이고, 4절의 "규칙을 더 늘리지 않는다"를 따른다.
- CLI가 `LawFetchError`·`OSError`만 잡는 점: OC가 든 문구를 가진 예외가 이 길로 나오는 경우는 없었다. 그대로 둔다.
- design.md §5 표 바로 뒤 "비교 화면은…" 줄: 이번 변경 전부터 있던 것이다. 이 단위에서는 고치지 않는다.

### 설계와 달라진 점

모두 `docs/design.md`·`docs/units/R0.md`에 반영했다(메모 "설계와 다른 점" 1~5). 6(경로 칸 `RelativeDir`)은 U4b에서 더한다.

- §5 예시의 스냅샷 경로를 `workspace/snapshots/…`(YAML 기준 상대 경로)로 고쳤다.
- §5 "알려진 남는 위험" 표: httpx 로거 줄에 "법령 수집은 수집하는 동안 로거 수준을 올린다"를 더했다. "OC가 짧으면 응답 거부가 잘못 걸릴 수 있음" 줄을 새로 넣었다.
- §6.1: 기준일의 뜻(그날 시행 중인 판, 같으면 공포가 늦은 판), `MST`+`efYd` 호출, API 주소는 코드에 고정, 수집 프록시 기본 `none`, 예제 기준일 2026-10-29를 적었다. 예제 스냅샷을 레포에 넣는 조건(출처표시 의무, 본문 XML만, 별표 제외, U9 전에 결정)도 적었다.
- R0.md: U4를 U4(수집·스냅샷)와 U4b(파싱·청킹)로 나눴다. 의존은 `U4 → U4b → U5`다.

구현이 메모와 다른 점은 위 "구현이 메모와 다른 점"에 있다. 설계를 바꾸는 것은 없다.
